# 西鸣人事管理系统 — 产品规格（逆向生成）

> 来源：从现有代码库逆向生成

## 产品目标与边界

### 核心目标

- 在本地/局域网内完成招聘与考勤的日常运营，避免敏感数据无必要外流。
- 把可确定的规则和重复操作自动化，把身份歧义、风控和外发动作停在人工确认处。
- 让每次导入、调整、阶段变化和自动化动作可回看、可解释、可恢复。

### 明确边界

- 考勤第一版不从打卡文件推断请假、加班、调休或出差。
- 不绕过 BOSS 验证码、App 确认、安全验证或风控页面。
- 自动化测试不向真实候选人发送消息；真实写操作需 HR 指定测试对象验收。
- 默认是单机/办公室局域网部署，不是多租户 SaaS。

## Architecture

### 架构模式

单仓库、模块化单体。开发时 Vue/Vite 与 Django REST 分离运行；生产构建后由 Django/Waitress 同源托管 SPA、API 和媒体文件。招聘自动化与简历智能处理都以数据库任务为边界，分别由 RPA Worker 和 AI Worker 轮询执行。

```text
用户浏览器
  └─ Vue SPA / Session + CSRF
       ├─ 考勤页面 ─────────────┐
       └─ 招聘页面 ─────────────┤
                                v
                     Django REST 模块化单体
       ┌────────────────┬───────────────┬───────────────┐
       │ accounts       │ attendance    │ recruitment   │
       │ 模型凭证       │ 人员/导入/核算 │ 招聘/审批/流程 │
       └────────────────┴───────────────┴───────┬───────┘
                                │               │ 数据库任务/事件
                    SQLite / PostgreSQL         v
                                │        本机 RPA Worker
                                │          ├─ 隔离浏览器
                                │          └─ BOSS CLI
                                └─ media + 本机 AI Worker
                                           ├─ Word/Excel/PDF/PNG 提取与 OCR
                                           └─ OpenAI 兼容模型（仅发送提取文本）
```

### 数据流

1. 普通页面请求由 `frontend/src/api.js` 统一添加同源凭证与 CSRF。
2. DRF Serializer 验证输入，Permission 检查角色/账号归属，ORM 完成事务。
3. 考勤导入在请求内解析并生成原始日记录、异常队列和核算结果。
4. 招聘自动化先创建不可变确认快照，再生成批次或 RPA 任务。
5. Worker 用本地 Token 租约任务，提交事件、证据和结果；服务端推进业务阶段。
6. 岗位依据和简历原文件留在 `media`。AI Worker 先本地提取文字块，再把文字块发送到账号配置的兼容模型；模型返回值必须通过字段、证据 ID 和分数校验后才能入库。

## 组件设计

### 前端 Shell

- 职责：登录恢复、模块切换、二级导航、用户菜单、模型切换入口。
- 依赖：Vue Router、Pinia auth store、`navigation.js`。
- 约束：当前模块的上次路由只保存在 `sessionStorage`。

### Model Profile Registry（2026-08-25）

- `UserModelProfile` 保存一个用户的多个 OpenAI 兼容模型连接；显示名称只用于工作台识别，API Key 继续由服务端加密且永不返回明文。用户之间的档案严格隔离。
- 每个用户最多一个活动档案。创建首个档案时自动启用；显式切换在同一事务内锁定该用户档案、更新活动标记，并把活动档案投影到既有 `UserModelCredential`。
- `UserModelCredential` 保留为“未来任务默认连接”的兼容投影。编辑活动档案、切换档案或使用旧凭证端点时都同步该投影；只有任务入队或 `WAITING_CONFIG` 首次绑定时读取它，Worker 执行与重试只读任务自己的不可变快照。
- Shell 中的“切换模型”是轻量选择器，只展示已保存档案、当前状态和“新增自定义模型”；新增/编辑通过独立表单抽屉完成。管理后台的模型页展示同一用户的完整档案列表，不复制数据。
- “切换模型”只改变未来任务采用的默认连接；已落库的标准版本、评分版本和审计记录继续保留各自模型快照。模型连接管理不提供聊天或推荐能力，因此 UI 不使用 Copilot 命名。
- 不提供前端密钥缓存、明文回显或跨用户共享。测试连接只针对指定档案，响应仅含档案、模型、可用状态和延迟。
- AI 任务入队时在服务端冻结当时活动连接的加密快照；Worker 只使用任务快照，不能在执行时重新读取已经切换的当前模型。无配置任务可在首次获得配置时绑定一次，绑定后重试也不得漂移。
- 自定义 API 地址默认只允许公网 HTTPS。回环、私网、链路本地、保留地址与重定向均失败关闭；确需本机或内网模型时只能由部署管理员通过环境允许列表显式开放。发送 Bearer 密钥或候选人文字前同时校验 DNS 结果和真实连接对端，不能只依赖表单 URL 语法。

### Recruitment Experience Architecture（2026-08-25）

- 招聘前端采用三工作区：`/recruitment/workbench`、`/recruitment/results`、`/recruitment/admin`。一级导航表达用户意图，不直接暴露底层资源类型。
- 招聘作业台是岗位级组合页面：复用 `RecruitmentJobContext`、岗位文档、岗位标准和标准工作流 API，在同页生成完整执行配置；执行仍通过既有版本启用与正式运行服务完成，审批、账号归属、身份复核和幂等规则不变。
- 结果中心是岗位/运行级读模型：组合 WorkflowRun、Campaign、HumanAttention、Application、Resume、Assessment 和阶段数据。前端按 `job/run` 请求令牌丢弃过期响应，刷新时从服务端恢复运行，不依赖组件内存。
- 管理后台是全局组合页面：集中职位同步、BOSS 账号与隔离浏览器、流程版本/画布、模型和系统诊断；岗位筛选不得隐式限制全局配置。
- 旧 `/recruitment`、`jobs`、`candidates`、`pipeline`、`automation`、`resumes` 路由保留兼容映射；迁移只改变呈现和入口，不复制或迁移领域数据。
- 第一轮采用现有资源 API 的前端适配层，不新增数据模型。后续若多请求一致性或幂等成为真实问题，再增加原子“创建招聘作业”和结果聚合端点。
- 对抗审查发现既有被动索简历与主动批量拉简历路径没有完整继承运行时安全门。三工作区上线前必须将 `request_resume` 视为外发动作，将主动搜索与逐份简历查看拆成可审计步骤；确认快照、日额度和执行前唯一身份复核必须在服务端强制，前端不能用“一键执行”绕过。
- 结果中心是统一业务入口，但不以删除能力为代价。不能安全内嵌的运行控制、人工处理、简历详情和阶段更新，应保留为不占一级导航的上下文详情页，直到对应组件迁入结果中心。

### Attendance 域

- 实体：人员、标签、策略、导入批次、原始打卡日、结果、跨日疑似。
- 服务：文件哈希、导入解析、人员匹配、规则核算、结果重算、跨日归属、Excel 导出。
- 关键不变量：同文件/期间防重复；结果按批次+员工唯一；跨日决策必须显式。

### Recruitment 域

- 实体：BOSS 账号、职位、候选人、应聘、简历、发现结果、外部身份、阶段历史。
- 服务：职位同步、候选发现/去重、沟通批次、简历归档、看板聚合、归档恢复。
- 关键不变量：同账号身份指纹唯一；候选人与职位的应聘唯一；简历哈希和版本唯一。

### Automation Runtime

- 实体：审批、执行批次、步骤、证据、RPA 任务/事件、流程模板/版本/运行/节点运行。
- 状态机：draft → approved → pending/running → succeeded/partial/failed/waiting_human。
- 安全门：账号授权、登录状态、人工确认、日额度、幂等键、目标重新核验、写操作不自动重试。
- 被动沟通中的索简历属于外部写动作；主动寻访中的每一次在线简历打开属于 `resume_view` 额度动作。批次审批可以冻结范围和上限，但不得把多次简历查看记为一次普通搜索。
- 只有平台稳定 ID（或平台原生等价标识）且适配器能在同一次原子动作中按该标识定位、复核并执行时，才允许自动索简历或打开在线简历。组合指纹只用于发现池和本地去重；“同名且唯一”或“先核验 ID、再按姓名点击”都不能替代动作阶段的稳定身份。缺少该契约时必须失败关闭并转人工提醒。
- 批量主动寻访可以在启动时保守预留额度，但必须为每次在线简历打开持久化任务级证据，并明确记录预留、实际尝试与未用额度处理。批量回写的业务变更要么全部提交，要么全部回滚；失败终态与审计必须在回滚后独立落库，不能留下部分候选/简历和运行中任务。
- 批准型动作只能由领域专用编排服务生成：通用 RPA 创建入口只开放状态检查、职位同步和会话同步；通用取消/重试不得拆离 Approval、ExecutionBatch、WorkflowNodeRun 或 SearchCampaign。`deep_search` 流程节点先生成冻结确认快照，批准后再由专用路径创建并绑定原节点的任务。
- 主动寻访的成功、转人工、执行失败、回执校验失败、取消与 Worker 租约超时都必须写脱敏任务级额度账本。未知执行次数使用 `actual_known=false`，不得采信未验证回执；超时或取消要在提交后恢复并终结关联工作流。暂停中的 Campaign 当前不支持续跑，必须明确提示新建任务。
- Workflow 取消会拒绝未执行确认、取消尚未进入适配器的任务与后续节点，并阻止 Worker 再领取；已经 LEASED/RUNNING 的外部动作不伪装中断，真实回执仍可完成审计，但 Run 保持取消。Campaign 停止由领域服务统一在提交后终结关联节点；`deep_search` 重试按 node attempt 生成全新的确认与任务，不复用旧失败记录。

### Resume Intelligence

- 实体：文件提取、岗位标准版本、结构化简历版本、评分版本、AI 处理任务。
- 岗位依据支持 DOC/DOCX 与多工作表 XLSX；Excel 块保留工作表名和行号，扫描 PDF/PNG 使用本地 OCR。
- 评分必须绑定 HR 已启用的标准；维度非零分必须引用简历原文证据，服务端重新计算总分。
- 硬性指标支持工作经验、最高学历、技能和城市等确定性规则；缺失信息进入核实问题。自动淘汰必须显式开启且由结构化字段复核，大模型结论不能单独触发，并写阶段历史和可追溯审计。
- 发布标准与每次评分均保留版本，不覆盖历史结果；模型 Key 按登录账号加密保存。

### 本地运行与运维

- `setup-local.ps1` 创建虚拟环境、安装依赖、构建前端、迁移并初始化管理员。
- `start-local.ps1` 启动 Waitress、一个 RPA Worker 和一个 AI Worker，健康检查后输出访问地址。
- `backup-local.ps1` 复制数据库和考勤原始文件到时间戳目录。

## 产品规格判断

### 已达成

- 两条业务链路都有真实的数据模型、接口、四态 UI 和回归测试。
- 高风险自动化的“人工在环”从提示语落实到了服务端约束和持久化证据。
- 本地交付、演示数据、备份和归档恢复形成可实际使用的基础。

### 未达成

- “统一人事系统”尚未有跨招聘/员工/考勤的领域关系和首页任务模型。
- Supervisor/Viewer 只有动作权限差异，没有数据范围差异。
- 复杂多轮招聘对话仍未纳入 Copilot；当前能力集中在岗位标准整理、简历结构化、证据评分和核实建议。
- [待确认] 缺少真实用户、业务量、月结时长、招聘转化等使用数据，无法判断市场效果。

## 技术决策记录

| 决策 | 观察到的原因 | 影响 |
|---|---|---|
| 同源 Session + CSRF | 本地部署、低运维复杂度 | 简单可靠；不适合直接拆成跨域多服务 |
| SQLite 默认、PostgreSQL 可选 | 单机即用并保留扩展路径 | 当前事务/并发模型仍主要按单机设计 |
| SPA 构建进 Django | 一条启动命令、一个端口 | 发布简单；前后端版本强绑定 |
| DB 任务租约而非消息队列 | 避免额外基础设施 | 适合当前规模；吞吐和可观测性上限较低 |
| 显式人工确认和不可变快照 | 外发、额度与身份风险高 | 牺牲一步效率换取可审计安全 |
| 组合指纹不等同平台身份 | BOSS 列表可能缺少稳定 ID | 防止同名误操作；执行前必须重新核验 |
| 本地加密模型 Key | 按登录账号持久化模型配置 | SECRET_KEY 丢失会使凭证不可解密 |
