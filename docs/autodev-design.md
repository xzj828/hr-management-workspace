# 西鸣人事管理系统 — 产品规格（逆向生成）

> 来源：从现有代码库逆向生成

## 产品目标与边界

### 核心目标

- 在本地/局域网内完成招聘与考勤的日常运营，避免敏感数据无必要外流。
- 把可确定的规则和重复操作自动化，把身份歧义、风控和外发动作停在人工确认处。
- 让每次导入、调整、阶段变化和自动化动作可回看、可解释、可恢复。

### 明确边界

- 考勤第一版不从打卡文件推断请假、加班、调休或出差。
- 不绕过 BOSS 验证码、App 确认、安全验证或风控页面。
- 自动化测试不向真实候选人发送消息；真实写操作需 HR 指定测试对象验收。
- 默认是单机/办公室局域网部署，不是多租户 SaaS。

## Architecture

### 架构模式

单仓库、模块化单体。开发时 Vue/Vite 与 Django REST 分离运行；生产构建后由 Django/Waitress 同源托管 SPA、API 和媒体文件。招聘自动化与简历智能处理都以数据库任务为边界，分别由 RPA Worker 和 AI Worker 轮询执行。

```text
用户浏览器
  └─ Vue SPA / Session + CSRF
       ├─ 考勤页面 ─────────────┐
       └─ 招聘页面 ─────────────┤
                                v
                     Django REST 模块化单体
       ┌────────────────┬───────────────┬───────────────┐
       │ accounts       │ attendance    │ recruitment   │
       │ 模型凭证       │ 人员/导入/核算 │ 招聘/审批/流程 │
       └────────────────┴───────────────┴───────┬───────┘
                                │               │ 数据库任务/事件
                    SQLite / PostgreSQL         v
                                │        本机 RPA Worker
                                │          ├─ 隔离浏览器
                                │          └─ BOSS CLI
                                └─ media + 本机 AI Worker
                                           ├─ Word/Excel/PDF/PNG 提取与 OCR
                                           └─ OpenAI 兼容模型（仅发送提取文本）
```

### 数据流

1. 普通页面请求由 `frontend/src/api.js` 统一添加同源凭证与 CSRF。
2. DRF Serializer 验证输入，Permission 检查角色/账号归属，ORM 完成事务。
3. 考勤导入在请求内解析并生成原始日记录、异常队列和核算结果。
4. 招聘自动化先创建不可变确认快照，再生成批次或 RPA 任务。
5. Worker 用本地 Token 租约任务，提交事件、证据和结果；服务端推进业务阶段。
6. 岗位依据和简历原文件留在 `media`。AI Worker 先本地提取文字块，再把文字块发送到账号配置的兼容模型；模型返回值必须通过字段、证据 ID 和分数校验后才能入库。

## 组件设计

### 前端 Shell

- 职责：登录恢复、模块切换、二级导航、用户菜单、Copilot 入口。
- 依赖：Vue Router、Pinia auth store、`navigation.js`。
- 约束：当前模块的上次路由只保存在 `sessionStorage`。

### Attendance 域

- 实体：人员、标签、策略、导入批次、原始打卡日、结果、跨日疑似。
- 服务：文件哈希、导入解析、人员匹配、规则核算、结果重算、跨日归属、Excel 导出。
- 关键不变量：同文件/期间防重复；结果按批次+员工唯一；跨日决策必须显式。

### Recruitment 域

- 实体：BOSS 账号、职位、候选人、应聘、简历、发现结果、外部身份、阶段历史。
- 服务：职位同步、候选发现/去重、沟通批次、简历归档、看板聚合、归档恢复。
- 关键不变量：同账号身份指纹唯一；候选人与职位的应聘唯一；简历哈希和版本唯一。

### Automation Runtime

- 实体：审批、执行批次、步骤、证据、RPA 任务/事件、流程模板/版本/运行/节点运行。
- 状态机：draft → approved → pending/running → succeeded/partial/failed/waiting_human。
- 安全门：账号授权、登录状态、人工确认、日额度、幂等键、目标重新核验、写操作不自动重试。

### Resume Intelligence

- 实体：文件提取、岗位标准版本、结构化简历版本、评分版本、AI 处理任务。
- 岗位依据支持 DOC/DOCX 与多工作表 XLSX；Excel 块保留工作表名和行号，扫描 PDF/PNG 使用本地 OCR。
- 评分必须绑定 HR 已启用的标准；维度非零分必须引用简历原文证据，服务端重新计算总分。
- 硬性指标支持工作经验、最高学历、技能和城市等确定性规则；缺失信息进入核实问题。自动淘汰必须显式开启且由结构化字段复核，大模型结论不能单独触发，并写阶段历史和可追溯审计。
- 发布标准与每次评分均保留版本，不覆盖历史结果；模型 Key 按登录账号加密保存。

### 本地运行与运维

- `setup-local.ps1` 创建虚拟环境、安装依赖、构建前端、迁移并初始化管理员。
- `start-local.ps1` 启动 Waitress、一个 RPA Worker 和一个 AI Worker，健康检查后输出访问地址。
- `backup-local.ps1` 复制数据库和考勤原始文件到时间戳目录。

## 产品规格判断

### 已达成

- 两条业务链路都有真实的数据模型、接口、四态 UI 和回归测试。
- 高风险自动化的“人工在环”从提示语落实到了服务端约束和持久化证据。
- 本地交付、演示数据、备份和归档恢复形成可实际使用的基础。

### 未达成

- “统一人事系统”尚未有跨招聘/员工/考勤的领域关系和首页任务模型。
- Supervisor/Viewer 只有动作权限差异，没有数据范围差异。
- 复杂多轮招聘对话仍未纳入 Copilot；当前能力集中在岗位标准整理、简历结构化、证据评分和核实建议。
- [待确认] 缺少真实用户、业务量、月结时长、招聘转化等使用数据，无法判断市场效果。

## 技术决策记录

| 决策 | 观察到的原因 | 影响 |
|---|---|---|
| 同源 Session + CSRF | 本地部署、低运维复杂度 | 简单可靠；不适合直接拆成跨域多服务 |
| SQLite 默认、PostgreSQL 可选 | 单机即用并保留扩展路径 | 当前事务/并发模型仍主要按单机设计 |
| SPA 构建进 Django | 一条启动命令、一个端口 | 发布简单；前后端版本强绑定 |
| DB 任务租约而非消息队列 | 避免额外基础设施 | 适合当前规模；吞吐和可观测性上限较低 |
| 显式人工确认和不可变快照 | 外发、额度与身份风险高 | 牺牲一步效率换取可审计安全 |
| 组合指纹不等同平台身份 | BOSS 列表可能缺少稳定 ID | 防止同名误操作；执行前必须重新核验 |
| 本地加密模型 Key | 按登录账号持久化模型配置 | SECRET_KEY 丢失会使凭证不可解密 |
