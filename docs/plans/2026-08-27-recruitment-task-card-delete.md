# 招聘任务卡片直接删除

日期：2026-08-27  
状态：已完成

## 目标

- 在招聘任务集合的每张卡片内提供删除入口，不要求 HR 先进入任务详情。
- 删除继续使用单次 `WorkflowRun` 归档语义，只移除目标卡片并保留运行结果与审计证据。

## 交互决策

1. 卡片底部将“查看与维护”保留为主操作，并增加次级危险按钮“删除”。
2. 已完成、失败或已停止的任务允许删除；运行、等待人工、暂停和安全收尾中的任务显示禁用按钮。
3. 点击可用按钮打开现有危险确认框；确认期间只禁用本次删除，失败原因保留在确认框中。
4. 删除成功后从当前内存列表即时移除该卡，不整页跳转；下一轮轮询继续以服务端未归档列表为准。

## 验收标准

- [x] 每张任务卡可看到删除按钮，终态可用、非终态禁用。
- [x] 点击终态删除按钮会显示保留范围确认文案。
- [x] 确认后调用对应 Run 的 `archive/` 接口且只移除目标卡片。
- [x] 接口失败或冲突时卡片不消失，确认框展示服务端原因。
- [x] 搜索、筛选、内部滚动和“查看与维护”入口保持正常。
- [x] 前端测试、生产构建和服务器运行态验收通过。

## 实现边界

- 不新增 API 或数据模型。
- 不物理删除任务、候选人、简历或审计记录。
- 不创建子 Agent。
