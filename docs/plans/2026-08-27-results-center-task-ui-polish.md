# 结果中心招聘任务 UI 打磨

> 日期：2026-08-27
> 类型：UI、视觉与响应式迭代
> 范围：`/recruitment/tasks`、`/recruitment/tasks/:planId`、`/recruitment/results`

## 问题证据

- 招聘任务集合页主要正文、表头、状态和控件大量使用 10–12px，1440px 屏幕下可读性和视觉质感不足。
- 原生下拉菜单、按钮和结果中心二级导航来自多组独立 scoped CSS，尺寸、圆角和层级不一致。
- 页头英文 kicker、统计卡说明和空态说明重复表达已有结构，增加噪音。
- 表格用固定窄列换取不换行，岗位、方案和操作信息在中等屏幕过早拥挤。
- 任务详情同时突出多个操作，状态卡和结果内容之间缺少清晰主次。

## 方案

- 为招聘任务集合页建立流体字号、间距、控件高度和圆角 token，保持现有青绿色设计语言。
- 简化二级导航、页头、统计卡和空态文案；错误、阻塞、删除后果与人工确认提示保持不变。
- 筛选区改为带真实 `AppIcon` 的统一输入/下拉控件；桌面为宽搜索 + 两个稳定宽度筛选，中屏和窄屏逐级换行。
- 桌面任务列表优先扩大岗位与方案列；中屏转双列卡片，窄屏转单列卡片，触控目标不低于 44px。
- 任务详情统一主/次/危险操作层级，提高状态信息与按钮可读性；嵌入业务结果继续复用同一读模型。
- 业务结果页同步提高导航、刷新按钮、筛选下拉和页签的稳定尺寸，避免两个子页面视觉割裂。

## 交互与状态

- 搜索、筛选、当前/已删除切换和任务跳转行为不变；焦点态使用清晰的青绿色描边。
- 宽屏使用表格扫描；中屏和窄屏只改变布局，不隐藏状态、版本、更新时间或操作。
- 页面只强调“创建新任务”或当前状态下的主要动作；危险操作保持独立危险色。
- Loading、Error、Empty、Normal、Archived 四态继续存在，正常态减少说明，异常态保留可执行恢复动作。
