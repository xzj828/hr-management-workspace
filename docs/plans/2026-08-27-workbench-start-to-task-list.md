日期：2026-08-27  
状态：已完成

## 问题

- 工作台“开始执行”成功后直接进入 `/recruitment/tasks/:planId` 详情页。
- 用户期望先进入结果中心的“招聘任务”集合，确认刚创建的任务与其他未删除任务都在列表中，再按需进入详情。

## 设计决策

1. 原子启动成功、草稿清理和下次空白工作台重置逻辑保持不变。
2. 成功跳转目标改为命名路由 `recruitment-tasks`，不携带详情页的 `planId/job/run` 参数。
3. 任务集合读取服务端正式 Run，因此新任务会与全部未删除任务一同出现；详情仍由卡片“查看与维护”进入。
4. 启动失败、冲突或前置检查阻塞时不跳转，继续保留工作台输入和恢复能力。
