# 西鸣人事招聘作业台参考图版 — UI/UX 设计

> 基于：`docs/autodev-ideation.md` + `docs/autodev-design.md` + 用户 2026-08-26 提供的视觉参考与逐轮反馈
> 平台：桌面优先 Web / Windows 本地与局域网
> 本文是招聘作业台最新专项真值：覆盖旧文档中的三步呈现，但不改变后端 Plan、安全门或 API 边界。

## 信息架构

```text
招聘管理
└─ 招聘作业台 /recruitment/workbench
   └─ 同一路由四步向导
      ├─ 01 职位与账号
      ├─ 02 招聘标准
      ├─ 03 执行方案
      └─ 04 执行前检查
```

- 全局招聘导航保持“招聘看板 / 招聘作业台 / 结果中心 / 管理后台”。
- 四步位于同一张卡内；桌面为左侧步骤栏，窄屏折叠为卡内顶部步骤摘要。
- `step=context|standard|plan|review` 只改变当前卡内任务，不离开作业台。
- 04 是独立切换页。检查清单、阻塞原因、处理入口、执行摘要和唯一“开始执行”不得出现在 03 内或其旁边。

## 用户流程

### 流程：准备并发起招聘作业

触发：HR 从招聘顶部导航进入“招聘作业台”，或从岗位上下文深链进入。

1. 用户在 01 看到在招职位和已授权执行账号，选择同一授权范围内的组合。
2. 用户点击“下一步：招聘标准”；若岗位或账号缺失，原位看到原因与管理后台入口。
3. 用户在 02 上传统一的“岗位参考资料”，补充核心要求与加分项。界面不再要求选择“候选人画像 / 招聘需求 / 其他标准”；上传内部固定使用兼容类别 `persona`。
4. 用户点击“下一步：执行方案”；上传可以稍后补充，文字要求与草稿继续保留。
5. 用户在 03 选择被动咨询或主动寻访，并配置相应流程与参数。
6. 用户点击“下一步：执行前检查”。该动作只切换到 04，不创建任务、不触发浏览器、不外发。
7. 用户在 04 查看岗位、账号、隔离浏览器、本机自动化服务、方案和参数的检查结果。阻塞项显示原因和处理入口。
8. 所有条件满足后，用户点击本页唯一的“开始执行”；系统按既有服务端原子命令创建/开启 Plan。
9. 已有 Plan 时，04 留在同一位置展示真实状态、停止/修改/继续/重新开启和结果中心入口。

完成：用户得到可审计的 Plan/运行状态并可前往结果中心。
异常：加载、上传、草稿恢复、版本冲突、Worker/CLI 离线、账号未就绪和正式动作失败都留在对应步骤，保留已有输入与恢复动作。

## 页面清单

| 页面 | 用途 | 对应功能 | 入口 |
|---|---|---|---|
| 01 职位与账号 | 冻结本次岗位和授权账号上下文 | 岗位/账号选择、缺失处理 | 作业台默认入口 |
| 02 招聘标准 | 收集岗位参考资料和文字标准 | 多文件上传、核心要求、加分项 | 01 下一步 |

## 页面详细设计

### 统一舞台与主卡

- 顶栏以下内容区使用高饱和青蓝舞台 `#00bfc1`，不影响其他路由。
- 桌面主卡约 `880 × 570px`，完整居中可见，外圆角 `30–32px`，只有一层柔和阴影。
- 左栏 `220–240px`、浅青背景；右区约 `640–660px`、白色背景。两区共享外框，不产生第二张浮卡。
- 桌面外框高度稳定。02/03/04 内容超出时只滚动右侧工作区，左步骤栏与外轮廓不跳变。

### 左步骤栏

- 顶部只显示“招聘准备”与一句说明，不显示 `XM RECRUIT` 等无业务价值英文。
- 四个步骤纵向排列：圆形编号、14px 步骤名、12px 状态。
- 当前步骤使用一层白色浅面板与实心青蓝编号；已完成使用青蓝描边编号；未开放降低对比度但保留文字。
- 不使用白底、描边、底线、实心编号四重强调。

### 右工作区排版

- 右区首屏只保留一个可见主标题，即当前步骤标题 `24–26px / 700`。
- “招聘作业台”作为全局位置已由顶部导航表达，不再与当前步骤标题竞争；隐藏重复英文和 `STEP 0X` kicker。
- 主说明、控件、字段标签使用 14px；辅助说明、状态和计数使用 12px；左栏标题 18px。
- 右区内边距 `28–32px`，主要表单宽 `500–530px`，区块间距 `20–24px`。

### 01 职位与账号

- 职位与账号上下排列，控件高 `48–50px`。
- 只显示业务就绪状态；CDP 端口、浏览器类型等技术详情不占首屏。
- 底部主按钮与表单同宽，青蓝实心；说明在按钮上方或弱化显示。

### 02 招聘标准

- 标题为“招聘标准”，说明上传岗位参考资料并补充文字要求。
- “岗位参考资料”上传区统一支持 DOC/DOCX/XLSX、多选和拖放；无用途选择器。
- 上传队列保留逐文件成功/失败和重试语义。
- 核心要求与加分项共享统一字号、标签结构和文本域高度。

### 03 执行方案

- 只呈现方案选择、工作流和当前方案需要的参数。
- 被动/主动方案使用同一圆角、单层选中描边和原生 radio 标记。
- 底部有“上一步”和唯一推进按钮“下一步：执行前检查”。
- 不呈现执行摘要、检查清单、阻塞原因或“开始执行”。

### 04 执行前检查

- 页头主标题“执行前检查”，说明此页才会发起正式动作。
- 顶部以紧凑摘要显示岗位、账号与方案；其下为连续检查列表。
- 每项同时使用图标与文字状态，失败项显示原因和“处理”链接，不能只靠颜色。
- 未运行时只有一个实心“开始执行”；禁用态紧邻显示第一个阻塞原因。
- 已运行时显示现有 `RecruitmentOperationControl`，继续遵守服务端真实状态与安全门。

## 状态设计

| 状态 | 用户看到什么 | 用户能做什么 |
|---|---|---|
| Loading | 同一分栏主卡骨架，左右轮廓稳定 | 等待数据恢复 |
| Empty（01） | 无职位/账号原因与唯一管理入口 | 去管理后台处理 |
| Empty（02） | 上传引导、空文字域，保留下一步说明 | 上传或先填写文字要求 |
| Normal | 当前步骤任务与单一推进动作 | 编辑、前进、返回 |
| Error | 错误贴近字段/上传/检查项，输入不清空 | 修正、重试或处理 |
| Blocked（04） | 完整检查列表、禁用开始按钮、首个阻塞原因 | 点击对应处理链接 |
| Running（04） | Plan 版本、真实运行状态和受控操作 | 停止、修改、继续、查看结果 |

### 排版

字体族：`Inter, PingFang SC, Microsoft YaHei, system-ui, sans-serif`。

| 层级 | 字号 | 字重 | 行高 | 用途 |
|---|---:|---:|---:|---|
| 当前任务标题 | 26px | 700 | 1.3 | 01/02/03/04 唯一主标题 |
| 左栏标题 | 18px | 700 | 1.4 | 招聘准备 |
| 正文/控件 | 14px | 400–700 | 1.55 | 标签、输入、主要说明、按钮 |
| 辅助 | 12px | 400–600 | 1.5 | 状态、帮助、计数 |

### 风格参数

- 间距基于 4px：`8 / 12 / 16 / 20 / 24 / 28 / 32px`。
- 主卡圆角 `30–32px`；输入/按钮/选项 `9–12px`；编号与状态圆形/胶囊。
- 主卡只有一层 `0 20px 60px rgba(4,75,78,.20)` 左右的柔和阴影；内部区域不再使用浮层阴影。
- 图标继续使用项目 `AppIcon` 自定义线性 SVG，默认 `currentColor`，禁止 emoji。

## 动效规范

### 基调

极简。动效只服务状态确认，不做装饰性页面入场或卡片上浮。

### 过渡参数

| 类型 | 时长 | 缓动 | 用途 |
|---|---:|---|---|
| 即时反馈 | 150ms | ease-out | hover、focus、radio |
| 标准状态 | 180ms | ease | 步骤选中、拖拽边框 |

### 场景方案

- 步骤切换：直接替换右区内容，不做滑屏。
- 数据加载：保留统一主卡骨架。
- 上传拖拽：仅改变边框和浅色背景。
- 成功/错误：沿用现有状态提示，不抖动。
- `prefers-reduced-motion`：关闭非必要过渡。

## 响应式策略

- `≥901px`：固定分栏主卡约 `880 × 570px`；左栏固定，右工作区独立纵向滚动。
- `721–900px`：主卡改为单列，步骤栏置顶，页面自然滚动；不保留桌面内部滚动。
- `≤720px`：四步摘要采用 2×2，表单/方案/检查列表单列，主按钮全宽；页面自身无横向溢出。
- 所有尺寸下保持一个共享外框，不让 04 重新成为独立卡片。

## 数据需求汇总

| 步骤 | 展示数据 | 用户操作 | 既有数据/业务边界 |
|---|---|---|---|
| 01 | 在招职位、职位描述可用状态、授权账号、账号业务就绪状态 | 选择职位与账号、前往管理后台 | 复用现有职位/账号读取与草稿恢复；不暴露技术端口为主信息 |
