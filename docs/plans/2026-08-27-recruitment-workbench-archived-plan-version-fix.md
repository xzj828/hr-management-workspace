# 招聘作业台归档方案版本修复

> 日期：2026-08-27
> 状态：已完成
> 范围：招聘作业台前端状态与回归测试；不改变 Plan API、数据模型或自动化安全门

## 问题

岗位已有已归档的 `RecruitmentAutomationPlan` 时，作业台把它读取到 `archivedPlan`，但编辑基线捕获与“以最新版本继续编辑”只读取 `currentPlan`。因此归档方案的真实 `control_version` 被降为 `0`，启动请求被服务端以 409 拒绝。

同时，作业台会把所有 409 的服务端 `detail` 覆盖成统一提示，导致用户无法判断实际冲突版本。

## 修复设计

1. 建立统一的可控制方案真值：未归档方案优先，否则使用已归档方案。
2. 编辑基线捕获、版本差异提示、重新基于最新版本以及启动命令都使用同一真值。
3. 继续保留服务端乐观并发保护，不自动覆盖基于旧版本的用户草稿。
4. 409 后刷新服务端状态，并在界面保留服务端返回的具体原因。

## 验收标准

- [x] 岗位只有已归档 Plan 时，启动请求使用该 Plan 的真实 `control_version`。
- [x] “以最新版本继续编辑”可把归档 Plan 的最新版本写入编辑基线。
- [x] 409 提示包含服务端原始 `detail` 和刷新结果说明。
- [x] 新建 Plan、未归档 Plan、幂等重试和轮询行为保持原有测试契约。
- [x] 作业台定向 Vitest 与前端生产构建通过。
