# 工作台招聘标准统一

日期：2026-08-27  
状态：已完成

## 问题

- 工作台上传的 DOC/DOCX/XLSX 会生成岗位标准草稿，但主动寻访只接受另行启用的标准。
- 工作台填写的核心要求和加分项只进入搜索参数，没有成为简历评分标准。
- Plan 启动校验和 Campaign 创建分别读取“当前已发布标准”，没有把同一版本冻结到启动快照。

## 设计决策

1. 招聘作业台“招聘标准”步骤是标准的唯一业务入口，不再要求 HR 跳转到简历页重复上传或发布。
2. 有手工核心要求/加分项时，服务端在原子启动命令内确定性编译并启用不可变 `JobStandardVersion`；核心项相对加分项采用 2:1 基础权重并归一化为 100。
3. 仅有岗位文档时，复用与当前文档版本完全一致、且已经生成完毕的标准；草稿由本次“开始执行”确认并启用。文档仍在生成或生成失败时返回可恢复原因，不要求重新上传。
4. 服务端把解析出的 `standard_id` 写入不可变 Plan Revision/Run 快照，创建 Campaign 时直接绑定该 ID，不再延迟读取可能变化的当前标准。
5. 敏感属性禁用、评分证据、版本不可变、AI 建议不替代 HR 决策等既有安全边界保持不变。

## 交互

- 执行前检查项改名为“本次招聘标准”。
- 手工输入和 Word/Excel 文档为二选一来源；已有已启用版本继续兼容。
- 文档标准未生成完毕时显示“正在生成/请稍后重试”，不显示“请上传评分标准”或跳转到另一个上传入口。

## 验收标准

- [x] 仅填写核心要求/加分项即可启动主动寻访，并冻结自动生成的已启用标准。
- [x] 仅上传 Word/Excel 且标准草稿已生成时，点击开始可直接确认并启动。
- [x] 文档仍在生成时不创建 Plan/Campaign/RPA 任务，错误明确且不要求重新上传。
- [x] 同一请求重试不重复创建标准；新任务标准与 Campaign 标准一致。
- [x] 前端不再要求另行上传“AI 简历评分标准”。
- [x] 后端回归、前端回归和生产构建通过；部署后健康检查通过。

## 验证记录

- Django recruitment 全量测试 490 项通过；系统检查通过且无迁移漂移。
- Vitest 全量测试 267 项通过；Vite 生产构建通过。
- 真实本机数据库的事务回滚 API 演练返回 201，Revision、Campaign 与审批冻结同一标准；没有创建外部 RPA 任务，回滚后任务总数不变。
- 已部署到本机/局域网服务；工作台生产资产包含新文案且不再包含旧的“先发布岗位评分标准”提示，Web/RPA/AI 服务健康。
