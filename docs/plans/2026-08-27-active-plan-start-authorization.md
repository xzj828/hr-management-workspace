# 标准主动寻访开始授权

日期：2026-08-27  
状态：实施中

## 问题

HR 已在招聘作业台确认岗位、关键词、候选筛选条件、目标合格简历数和 AI 最大分析份数，并点击“开始执行任务”，标准主动寻访仍会在“搜索、拉取并 AI 初筛”节点生成第二次人工确认。该确认没有新增信息，导致任务停在 `waiting_human`，用户误以为自动化没有继续执行。

## 设计决策

1. 仅系统托管的标准主动寻访 Plan 将 HR 的“开始执行”冻结为当前 Revision/Generation 的 `search_and_pull_resumes` 授权；自定义流程和直接创建的 Campaign 不继承该授权。
2. 搜索节点仍创建不可变 `AutomationApproval` 快照。服务端确认 Run 授权、操作者、Revision 和 Generation 一致后，调用既有审批服务自动批准，再调用既有 Campaign 启动服务预占搜索与在线简历查看额度并创建 RPA 任务。
3. 不删除账号权限、登录状态、额度、稳定身份、动作前后 checkpoint、结果证据、幂等和审计控制。授权范围外、额度不足、Revision/Generation 过期或快照变化均失败关闭。
4. 主动寻访完成后的批量打招呼是新的外发动作，继续单独冻结候选范围和话术并要求 HR 确认。
5. 已经停在旧重复确认节点、且快照仍属于当前运行代际的标准 Plan，可由显式恢复操作按同一服务链批准并启动；不得批量迁移或自动批准未知旧任务。

## 交互

- 执行前检查明确显示本次最大在线简历查看额度，并说明点击开始即授权冻结范围。
- 点击开始后直接进入“运行中”，不再显示“搜索、拉取并 AI 初筛”的人工处理卡。
- 额度不足、账号不可用、风控或稳定身份无法复核时，展示对应真实阻塞原因；这些运行时例外仍可进入人工处理。

## 验收标准

- [ ] 标准主动寻访点击开始后，Approval 为已批准、额度已预占、RPA Task 已创建，Run/节点不处于重复确认的 `waiting_human`。
- [ ] 重复开始请求不重复创建审批、任务或重复扣减额度。
- [ ] 自定义工作流和直接 Campaign 仍等待人工审批。
- [ ] 额度不足、旧 Revision/Generation 和快照不一致均不创建外部任务。
- [ ] 当前真实等待任务可恢复并由本机 Worker 实际执行，运行证据可回看。
