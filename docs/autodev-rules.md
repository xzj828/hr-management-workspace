# 西鸣人事管理系统 — 编码规则

> 来源：从现有代码库逆向生成

## 技术栈约束

- 前端使用 Vue 3.5、Vue Router 4.5、Pinia 3、ECharts 6、Vite 7；不要引入第二套 UI 框架。
- 后端使用 Django 5.2、DRF 3.16；默认 SQLite，保留 PostgreSQL 环境变量路径。
- Python 依赖维护在 `backend/requirements.txt`，前端依赖维护在 `frontend/package.json`。
- 本地图标通过 `AppIcon.vue` 和 `frontend/src/icons/` 使用，业务 UI 不依赖网络图标。

## 文件与命名

- Vue 页面以 `*View.vue` 命名，可复用交互拆到 `components/`；页面测试与源文件邻近放置为 `*.test.js`。
- Django 域按 `models/serializers/views/services/tests` 组织；复杂规则优先进入 `services/`，View 负责鉴权和 HTTP 编排。
- API 路径使用小写 kebab-case；Python 使用 snake_case；Vue/JS 变量使用 camelCase。
- 复用全局 `panel`、按钮、表格、状态徽标、弹窗和抽屉样式，新增样式保持作用域明确。

## 前端约定

- 请求统一通过 `frontend/src/api.js`，保持 `credentials: include` 与 CSRF 处理。
- 列表响应通过 `listItems()` 兼容分页与非分页数据。
- 页面异步操作至少处理 loading、error、empty、normal 四态；高风险操作使用确认弹窗/抽屉。
- 路由必须声明业务 `module` 与 `title`；公共演示页必须明确 `meta.public`。
- 不在前端持久化 API Key、Worker Token、候选人身份秘密或银行完整字段。

## 后端与 API 约定

- 普通 API 使用 SessionAuthentication；写操作使用 `HRWritePermission`/`HRPermission` 或招聘等价权限。
- BOSS 账号相关查询和动作必须按当前用户授权范围过滤，不能只依赖前端隐藏。
- 错误统一返回可读的 `detail`，字段校验可返回字段映射；冲突使用 409，权限使用 403。
- 创建外发/额度动作必须有 UUID 请求标识、幂等键、服务端确认快照和审计记录。
- Worker 只使用独立 Token 访问白名单端点；租约、心跳和完成回写必须保持事务性。
- 文件上传限制类型、大小和路径；简历必须验证 PDF、计算 SHA-256 并保留版本。

## 自动化安全红线

- 不绕过验证码、App 确认、安全验证、风控或平台限制。
- 组合指纹只能用于发现池和本地去重，不能单独作为外发目标身份。
- 写操作失败或结果不确定时不得自动重试发送；成功项不得重复执行。
- 正式流程必须使用已启用不可变版本，发送节点前必须存在人工确认节点。
- 浏览器用户目录必须位于受控 `rpa_profiles` 根目录，调试端口只允许回环与受管范围。

## 数据规则

- 同一考勤文件哈希和期间不能重复导入；源文件必须保留。
- 跨日疑似必须显式选择“归前一天”或“保留当天”。
- 请假、加班、调休、出差等不能由打卡记录可靠推断，保持人工调整与规则轨迹。
- 归档优先于硬删除；已启用流程版本、历史任务和审计证据必须保留。

## 质量红线

- 禁止占位：提交范围内不得新增 TODO、空函数体或无说明的 `pass`。
- 禁止把演示/假数据混入真实业务数据；演示数据必须使用明确的 `is_demo` 标记或独立演示数据库。
- 禁止降阶：不能为了让测试通过而绕开服务端权限、确认、身份核验、幂等或审计。
- 版本正确：新增 API 或依赖前核对当前实际版本和官方文档。
- 前端变更运行 Vitest 与生产构建；后端变更运行对应 Django 测试；高风险流程增加失败与越权用例。

## 禁止模式

- 不从浏览器 DOM 名称直接认定候选人唯一身份。
- 不把密钥、Token、完整连接串写入日志、文档、前端包或测试快照。
- 不使用日常浏览器资料目录执行 RPA。
- 不在普通功能迭代中删除用户数据库、media、备份或已有设计文档。
