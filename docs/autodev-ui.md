> 来源：从现有代码库逆向生成
> 基于：`autodev-ideation.md` + `autodev-design.md`
> 平台：桌面优先的 Web / Windows 本地与局域网

## 信息架构

```text
登录
└─ 应用 Shell
   ├─ 招聘管理
   │  ├─ 招聘作业台
   │  ├─ 结果中心
   │  │  ├─ 招聘任务
   │  │  └─ 业务结果
   │  └─ 管理后台
   ├─ 考勤管理
   │  ├─ 考勤看板（当前默认首页）
   │  ├─ 人员管理
   │  ├─ 导入中心
   │  ├─ 核算结果
   │  ├─ 异常审核
   │  └─ 规则与标签
   └─ 用户菜单
```

左侧导航切换业务模块，顶部导航切换模块内工作区。每个模块最后访问的页面保存在当前会话；刷新不丢失，关闭会话后恢复默认。旧六页面招聘路由仅作兼容入口，不再作为一级导航。

## 核心用户流程

### 流程 1：月度考勤核算

1. HR 在“人员管理”维护工号、姓名/别名、部门、策略与标签。
2. 在“导入中心”选择 `.xlsx`、年份、月份和默认应出勤天数。
3. 系统校验文件类型/大小/重复哈希，解析并按工号→姓名→别名匹配。
4. HR 在“异常审核”逐条决定跨日记录归属。
5. 在“核算结果”查看规则轨迹，补充请假/加班/人工调整并确认。
6. 导出 Excel；看板按月份范围和部门聚合趋势与质量。

### 流程 2：招聘候选人推进

1. 管理员在“管理后台”添加 BOSS 账号、启动隔离浏览器并同步职位。
2. HR 在“招聘作业台”选择职位，上传画像/需求文件并补充核心要求和加分项。
3. HR 选择被动咨询或主动寻访方案；主动方案继续设置来源、关键词、目标简历数和最大扫描数。
4. HR 在执行方案页点击“检查并开始执行”后进入执行前检查；所有条件满足时前端自动调用一次服务端原子 Plan 命令。对标准被动方案，这次点击同时授权当前不可变修订/代际按冻结话术自动求简历；对标准主动方案，这次点击同时授权按冻结搜索条件和最大在线简历查看数执行搜索拉取；两者后续都不再弹出重复确认。身份歧义、额度、风控和结果不确定仍转人工或失败关闭。该一次性启动意图不跨刷新、深链或历史导航恢复，阻塞和失败时保留原因与手动重试。
5. 创建成功后进入结果中心的招聘任务集合 `/recruitment/tasks`，让刚创建的 Run 与其他未删除任务同时可见；任务卡不再设置“查看与维护”按钮，点击整张卡片打开背景虚化的任务概览卡片，展示岗位、方案版本、运行编号、实时状态和简要执行情况。独立详情路由仍承接当前 Run 的“停止任务”“停止并修改”“继续”“重新开启”和“删除任务”。`stopping` 明确说明当前原子动作正在安全收尾。
6. 工作台在成功回执后清除本次草稿，并保证下次进入时回到未选择岗位的 Step 1；工作台不得继续渲染任务列表、运行控制或运行期人工事项。启动失败或冲突时保留全部输入。结果中心集中展示运行进度、人工介入、候选人、简历/评分、失败原因和阶段推进；标准被动任务显示“开始执行已包含求简历授权”，标准主动任务显示“开始执行已包含本轮搜索与简历查看授权”，两者都不展示重复确认收件箱，后续外发确认与身份复核规则保持不变。
7. “候选人与简历”使用一个连续排名表展示全部应聘；点击行内查看动作在本页打开原始简历与分析报告。HR 可多选、确认通过/未通过，并在专用确认抽屉中决定是否把未通过通知加入安全执行队列。

### 流程 3：流程自动化

1. 在“流程编排”拖放安全节点并连线。
2. 保存产生不可变草稿版本；校验无环、账号已绑定、发送前有人审节点。
3. 试运行只演练状态机，不创建 RPA/审批工作。
4. 启用版本后选择职位并显式确认正式运行。
5. 运行在人工节点暂停；HR 通过/跳过，失败节点可显式重试。
6. 可暂停、恢复或取消；事件、步骤和任务保留审计链。

## 页面详细设计

### 应用 Shell

- 左侧 244px 深色模块栏，可折叠为 82px；底部显示本地服务状态。
- 顶部 64px 粘性导航；招聘模块依次显示招聘看板、作业台、结果中心、管理后台，并提供“切换模型”入口。
- 内容区最大宽度 1660px，桌面左右留白 34px。
- 用户菜单承载角色、“新增自定义模型”和退出；完整模型管理仍在招聘管理后台，避免用一个新增表单冒充管理页。
- “切换模型”点击后在按钮下方打开选择菜单：顶部说明当前模型；中部逐行展示已保存档案的名称、模型名和活动文字状态；底部提供唯一的“新增自定义模型”动作。选择另一档案后立即关闭菜单并以状态提示确认，不进入管理页面。
- 新增/编辑档案使用表单抽屉，字段依次为“配置名称、API 地址、模型名称、API Key”；主操作为“保存并切换”。已保存密钥只展示末四位且编辑时允许留空沿用。表单错误不清空输入，Escape/遮罩/关闭按钮可退出。

### 考勤页面组

- 看板：期间/部门筛选 → 4 个 KPI → 日趋势/部门对比 → 导入质量/待办；数字可下钻。
- 人员：顶部搜索和新增；主体为人员表格；宽弹窗承载主数据、银行和考勤配置。
- 导入：用 STEP 01/02 双面板表达文件与核算期间，主按钮触发同步处理；下方保留历史批次。
- 结果：批次选择与导出在页头，密集表格显示核算构成；人工调整用弹窗渐进披露。
- 异常：按待审核/全部分段，卡片同时展示前一天、当天、打卡文本和决策按钮。
- 规则：策略和标签分栏卡片，点击卡片编辑；说明强调策略、标签、权限互相独立。

### 招聘页面组

- 招聘看板：跨岗位全局摘要和工作分流，是首次进入招聘模块的默认页；会话内仍记住最后访问的招聘页面。`/recruitment` 必须渲染真实看板，不能把 `overview` 归一为结果中心的“需要处理”。桌面首屏采用左侧“今日优先”主卡、右侧“职位进度 + 风险提醒”侧栏、底部“关键数据”横向指标条的单屏结构；招聘看板路由使用 284px 深色侧栏与 75px 顶栏，其余页面保持既有壳层尺寸。核心正文与控件保持至少 12–14px 的稳定可读性。看板提供创建招聘任务主入口，并显式处理 Loading、Error/重试、Empty、Normal 四态。
- 招聘作业台：保持单一路由，以 `step=context|standard|plan` 呈现三页向导。顶部步骤条显示“选择本次作业 → 招聘标准 → 执行方案”，当前页只承载一个任务；完成本步动作后进入下一页，Step 2/3 可返回上一步且保留岗位草稿。
- 招聘标准页复用考勤导入的桌面上传语言：大面积虚线区域同时支持拖入和点击选择，允许 DOC/DOCX/XLSX 多文件、单文件最大 25MB；逐文件展示成功/失败，部分失败不重传成功项。
- 执行前检查位于独立 Step 4；Step 3 的“检查并开始执行”记录一次性启动意图，Step 4 在检查全部通过后自动发出原子启动命令。刷新、深链和历史导航进入 Step 4 不自动运行；阻塞或失败时保留手动“开始执行”重试。启动成功后进入招聘任务集合，先显示刚创建任务与所有未删除任务；HR 从卡片进入独立详情后查看真实状态、结果和当前任务控制。作业台通过“继续创建任务”以空白 Step 1 重新开始。
- 结果中心：在内容区顶部固定提供“招聘任务 / 业务结果”二级导航。招聘任务页跨岗位展示当前 Plan，支持关键词、运行状态和方案类型筛选；整卡点击打开统一的背景虚化任务概览，不在卡片中重复设置查看按钮。列表每 5 秒局部同步，不在集合页堆叠统计摘要、当前/已删除切换或同步时间栏。业务结果页继续提供岗位、运行、状态和时间筛选；默认优先“需要处理”，其余为“任务结果、候选人与简历、招聘进度”内部视图。业务结果在前，技术日志默认折叠。“候选人与简历”改为一个连续排名表，不再按通过/未通过拆页，也不跳转旧简历页面。
- 候选排名只比较当前简历、最新结构化版本和当前已发布标准下的可比评分。已评分按总分降序并用稳定 ID 打破平分；无简历、未评分、处理中和失败仍显示在末尾，排名为 `—`，不能被推断为 0 分或未通过。
- 每行分别显示招聘阶段、AI 初筛建议、得分/置信度、简历状态、HR 结论和通知状态。AI 建议文案必须带“AI”前缀；HR 结论只有显式人工操作才能产生，状态不能只靠红绿颜色表达。
- 主动寻访数量字段使用业务口径：“目标合格简历数”是 AI 建议进一步沟通的目标数，“AI 最大分析份数”是 AI 最多完成结构化与评分的简历数。运行结果分别展示“已拉取、AI 已分析/上限、AI 合格/目标”，不得再用“扫描”同时表示候选列表浏览和 AI 评分。
- 作业台“招聘标准”步骤中的 Word/Excel 与手工核心要求/加分项就是本次主动寻访标准，二者至少提供一种；执行前检查不得再要求到其他页面上传“AI 评分标准”。手工输入可直接开始，只有文档时需等待文档标准生成完成；“开始执行”同时确认并冻结本次标准版本。
- 主动寻访停止原因必须显示中文业务文案。达到合格目标、达到 AI 分析上限、候选池不足、等待模型配置、AI 处理失败和人工停止需要可区分；内部枚举值不得直接展示给 HR。
- AI 合格候选人进入现有连续排名表。HR 可按 AI 建议筛选并多选，确认一份统一话术后一次提交批量打招呼；AI 建议不替代 HR 选择，审批成功只表示加入逐人顺序队列。
- 点击候选人姓名或“查看简历与报告”在结果中心打开右侧详情抽屉，复用原件预览、结构化信息、维度评分、证据、硬性条件冲突、核实问题和历史版本。抽屉写入 `application/resume` 查询参数，刷新可恢复、浏览器返回可关闭；桌面右侧展开，窄屏全屏。
- 多选后出现单一批量操作条，提供“确认通过”和“确认未通过”。未通过确认抽屉展示岗位、候选人清单、内部原因、最终中性通知文案、账号与前置检查，并提供“仅保存 HR 未通过结论”和“确认未通过并加入通知队列”；不得使用“立即发送”。
- HR 结论与通知结果分开呈现。批量执行后持续展示已发送、等待人工、失败和结果不确定的逐项汇总；准备/批准失败时保留选择、原因和文案，已成功项不得再次选入同一通知。
- 排名表使用原生 `table/th`、排序列 `aria-sort`、带候选人名称的 checkbox 标签；详情与确认抽屉使用 `role=dialog`、Escape、初始焦点和关闭后返焦。小屏转为分隔行列表，批量条适配安全区域并保留至少 44px 触控目标。
- 管理后台：单一路由内以子导航切换“职位同步、BOSS 账号与浏览器、流程方案、模型管理、系统诊断”；根据角色隐藏未授权模块，API 仍是最终权限边界。
- BOSS 账号页采用状态驱动交互：Worker/CLI 全局阻塞在账号区域顶部持续显示；账号动作在当前账号内显示“排队 → 正在打开 → 等待扫码 → 正在确认 → 已连接”，并每 5 秒自动收敛。Worker 离线时不得制造无法执行的任务。
- 账号主动作随状态变化：浏览器停止时“打开登录窗口”，等待登录时“聚焦登录窗口”，风控时“打开验证窗口”，就绪后降级为次级“重新打开”；检查状态只在错误或状态过期时作为辅助动作。BOSS 密码不保存、不代填。
- 账号的 CDP 端口、隔离目录和可执行文件属于技术详情，默认折叠；业务状态、最近确认时间、原因和下一步必须在 3 秒内可见，并用文本而非仅颜色表达。
- 模型管理：以列表展示当前登录用户的所有模型档案，活动项显示“当前使用”；每项提供切换、编辑、测试连接，页头提供“新增自定义模型”。模型为空时解释用途并给出同一新增动作，不出现 Copilot 或未开放功能占位。
- 生命周期操作：账号、职位、流程和任务各自提供“当前 / 已归档”切换，不能用一个全局归档开关污染其他子模块或账号运行态。当前列表的归档、删除等低频动作进入行级次级操作；归档列表直接提供“恢复”。职位同步文案只使用“同步到系统/已同步职位”，“归档”专指从当前业务列表移除。
- 归档必须二次确认并说明保留范围；恢复不需要确认。账号归档保留隔离目录和历史任务，职位归档不会操作 BOSS 线上职位，流程归档保留版本与运行，任务归档保留事件和证据。仅流程草稿与模型配置使用“永久删除”，并明确不可恢复。
- 模型配置删除确认必须说明将擦除 API 地址和加密 Key；删除当前模型后，新 AI 任务等待配置，但已有任务使用冻结快照继续执行。
- 功能迁移采用组合而非复制：岗位文档和标准编辑组件进入作业台；候选人、流程、简历智能组件进入结果中心；账号、任务、画布和职位同步进入管理后台。

### 招聘工作区四态与反馈

- 作业台 Loading：分区局部骨架，开始按钮显示“正在检查运行条件”；Empty：无职位/账号时只展示对应解决入口；Error：错误贴近字段且保留输入；Success：完成 Plan/Run 回执校验后进入招聘任务集合，新任务由集合真实读模型展示。停止请求已提交但仍有在途动作时显示“正在停止”，不提前显示“已停止”。
- 结果中心 Loading：保留上次成功内容并局部刷新；Empty：提供返回作业台；Error：区分局部数据失败、候选人失败和整次运行停止；Normal：人工事项置顶并支持筛选。
- 管理后台 Empty：按子模块引导添加账号、同步职位、定义方案或模型；浏览器未启动时只开放登录窗口恢复路径，其他动作明确阻塞原因。Worker 或 CLI 未就绪时不创建登录、同步或正式执行任务。
- 管理后台 Archived Empty：明确“暂无已归档记录”并提供返回当前列表；归档/删除失败必须保留原记录和确认上下文，不能显示成功或误清空列表。
- 模型选择 Loading：菜单保留轮廓并显示“正在读取模型”；Empty：只显示“尚未配置模型”和新增动作；Normal：当前模型有文字与勾选双重标识；Error：保留上次成功列表并提供重试。切换期间只禁用模型菜单，不阻塞当前业务页。

## 四态设计

| 页面组 | Loading | Empty | Normal | Error |
|---|---|---|---|---|
| 登录/Shell | 品牌呼吸标记 | 不适用 | 登录表单/应用壳 | 表单内错误 |
| 两个看板 | 首次加载变量，当前多为内容延迟出现 | 引导导入或连接账号 | KPI、任务、图表 | 页面错误 + 重试/保留导航 |

| 文件/自动化 | 主按钮进行中文案、状态轮询 | 引导上传/添加账号/创建批次 | 状态徽标 + 时间线 | 可读错误、等待人工、显式重试 |

### 招聘任务集合与独立详情页（W16，2026-08-27）

- 路由：`/recruitment/tasks` 是结果中心内可见的跨岗位任务集合页；`/recruitment/tasks/:planId` 是其详情子页面。二者不增加招聘一级导航，均使顶部“结果中心”保持高亮。
- 入口：结果中心内容区的“招聘任务 / 业务结果”二级导航始终可见；作业台启动成功自动进入详情；业务结果中的任务运行行也可进入；详情面包屑返回招聘任务集合。
- 集合页：页头提供“创建新任务”，筛选区直接提供关键词、状态和类型；不显示重复的任务统计摘要、当前/已删除切换或自动更新时间栏。任务卡展示岗位、方案类型、不可变版本、运行编号、真实状态与更新时间；整卡是详情触发区，不再显示“查看与维护”按钮，卡片内仅保留次级危险操作“删除”。Loading/Error/Empty/Normal 四态不阻断前往工作台创建任务。
- 头部：结果中心面包屑、岗位与方案类型、方案版本/运行编号、真实服务端状态；右侧按状态显示“继续创建任务”“停止任务”“停止并修改”“修改任务”“重新开启”“删除任务”或“恢复任务”。
- 主体：直接复用结果中心的 KPI、需要处理、任务结果、候选人与简历、招聘进度视图。任务路由固定 `job/run` 上下文，默认打开任务结果；业务界面只展示中文业务步骤、当前状态和需要人工处理的动作，不展示原始节点键或事件日志，技术诊断留在管理后台边界内。
- 视觉：完整复用结果中心的 `Ink/Slate/Muted/Line/Paper/Canvas/Teal/Amber/Red`、Inter/PingFang SC 字体、响应式 clamp 间距、15–20px 面板圆角、细边框与轻阴影；不新增色板或 UI 框架。
- Loading：集合页保留筛选骨架，详情页保留任务头部与结果区局部骨架；Error：集合页可重试且保留创建入口，详情读取失败可返回招聘任务；Normal：列表和详情局部轮询；Archived：既有详情深链保留结果只读并提供恢复，集合页不单独占用切换栏。
- 删除交互：任务集合卡片和独立详情均提供删除入口；活动、暂停、等待人工和停止中禁用，终态点击后使用危险确认框，明确“从当前任务列表移除但保留历史结果和审计证据”。集合页确认成功后只即时移除目标卡片，不跳转页面、不影响其他任务。
- 作业台连续创建：启动成功后只清除对应草稿；“继续创建任务”进入 `new=1` 的空白 Step 1，不自动选择上次岗位。修改入口以 `editPlan` 回填当前 Revision，并在停止安全收尾前禁止重新执行。
- 响应式：桌面头部状态与操作并排；中屏换行；窄屏操作为全宽按钮，结果中心现有表格卡片化规则继续生效。
- 结果中心密度：招聘任务集合、任务详情与业务结果共享可读性下限。正文和控件不得依赖 10–12px 作为主要信息字号；筛选、按钮与下拉菜单在桌面保持 44–48px 的稳定高度，并通过流体 token 在超宽或缩放视口中适度增长。
- 任务列表布局：所有桌面宽度统一使用内容卡片，宽屏三列、中屏双列、窄屏单列；卡片用方案类型视觉区、岗位、版本、运行编号、状态和更新时间形成稳定信息层级，整卡点击后打开统一的白色任务概览卡片，周围页面使用半透明遮罩与背景虚化。页面不得通过压缩主要文字来避免换行或横向溢出。
- 任务执行概览卡片：桌面采用约 886×833px 的居中白色弹窗，标题栏为“任务执行中”；主体按 265px 左侧运行摘要与右侧执行判断分栏。左侧依次展示岗位、方案类型、真实状态、运行编号、环形整体进度、开始时间和执行账号；右侧依次展示当前步骤、检索/分析/符合要求三个真实计数、下一步说明和是否需要 HR 处理。底部固定展示准备、检索、分析、归档四阶段流程轴与唯一“查看运行记录”按钮。窄屏改为单列并保持弹窗内部滚动，关闭、Escape 和焦点循环沿用统一详情卡片行为。

### 统一证据详情卡片（2026-08-27）

- 所有招聘详情采用居中白色卡片、16px 圆角、柔和阴影和背景虚化；卡片支持关闭按钮、遮罩点击、Escape 和键盘焦点循环。
- AI 简历分析卡片禁止使用分页、页签、评分仪表盘或多列信息卡。内容顺序固定为候选人摘要、目标岗位、约 200 字且自然分成三段的 AI 分析报告、关键信息标签和唯一“查看原始简历”按钮。
- PDF 或在线简历截图默认不加载、不展示；只有用户点击“查看原始简历”后才挂载独立的大型预览卡片，不在 AI 报告卡片或侧边抽屉内嵌原文件。
- AI 报告“查看原始简历”与简历中心“原件”统一使用同一文档预览器。PDF 与图片共享遮罩、工具栏与滚动内容区；缩放范围固定为 50%–200%，步长 25%，并支持复位、展开、下载与关闭。
- `evidence-level-v1` 详情在报告前独立展示后端总分、60 分线、系统建议、标准版本和策略版本；报告正文只读取后端持久化内容，不再由浏览器拼接。报告失败时保留分数与证据明细，并提供不改变分数的“重试分析报告”。
- 新版维度明细展示权重、L0–L4、两位小数得分、原因和缺失/矛盾状态。列表至少显示一位小数，避免 59.99 四舍五入成 60 后与未及格标识冲突。
- 任务列表高度：招聘任务集合页锁定在应用可用视口内，不随任务卡数量增加而撑高外层页面；二级导航、页头和筛选区保持可见，卡片列表占用剩余高度并独立纵向滚动。Loading、Error、Empty 与筛选无结果状态沿用同一高度边界。
- 文案层级：正常态只保留能帮助判断状态或完成下一步的说明。页头英文 kicker、统计卡重复解释、空态重复去向和无行动价值的同步提示不占主要视觉层级；错误、阻塞、危险操作后果和人工确认规则必须保留。
- 控件层级：页面只保留一个视觉主操作；次级、危险与文字操作按语义区分。结果中心二级导航使用简洁分段式入口，不重复解释当前页面已经表达的功能。
- 页面职责纠偏：作业台仅保留四步配置、执行前检查、启动反馈和失败恢复，不展示任何已执行任务卡片。多任务入口由结果中心可见的“招聘任务”集合页承担；任务状态和修改、停止、删除等操作由其独立详情子页面承担。

### 招聘任务卡片持久展示修订（2026-08-27）

- 一张任务卡对应一次“开始执行”产生的正式运行，而不是岗位级 Plan；同一岗位连续创建的历史任务全部保留，只有用户显式删除某次任务后该卡才从当前集合移除。
- 卡片仍使用现有三/二/一列内容卡布局，但版本、运行编号、状态和更新时间均来自该次 Run/Revision，不允许被 Plan 最新值覆盖。
