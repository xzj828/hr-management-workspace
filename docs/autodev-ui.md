## 信息架构

```text

└─ 应用 Shell

   │  ├─ 结果中心

   ├─ 考勤管理

   │  ├─ 人员管理

   │  ├─ 核算结果
```

左侧导航切换业务模块，顶部导航切换模块内工作区。每个模块最后访问的页面保存在当前会话；刷新不丢失，关闭会话后恢复默认。旧六页面招聘路由仅作兼容入口，不再作为一级导航。

## 核心用户流程

### 流程 1：月度考勤核算

1. HR 在“人员管理”维护工号、姓名/别名、部门、策略与标签。
2. 在“导入中心”选择 `.xlsx`、年份、月份和默认应出勤天数。
3. 系统校验文件类型/大小/重复哈希，解析并按工号→姓名→别名匹配。
4. HR 在“异常审核”逐条决定跨日记录归属。
5. 在“核算结果”查看规则轨迹，补充请假/加班/人工调整并确认。
6. 导出 Excel；看板按月份范围和部门聚合趋势与质量。

### 流程 2：招聘候选人推进

1. 管理员在“管理后台”添加 BOSS 账号、启动隔离浏览器并同步职位。
2. HR 在“招聘作业台”选择职位，上传画像/需求文件并补充核心要求和加分项。
3. HR 选择被动咨询或主动寻访方案；主动方案继续设置来源、关键词、目标简历数和最大扫描数。
4. 作业台执行前检查岗位、账号、浏览器、方案与数量；所有条件满足后只提供一个“开始执行”主动作。
5. 创建成功后显示任务编号、当前状态和“查看结果”，详细信息进入“结果中心”。
6. 结果中心集中展示运行进度、人工介入、候选人、简历/评分、失败原因和阶段推进；外发确认与身份复核规则保持不变。

### 流程 3：流程自动化

1. 在“流程编排”拖放安全节点并连线。
2. 保存产生不可变草稿版本；校验无环、账号已绑定、发送前有人审节点。
3. 试运行只演练状态机，不创建 RPA/审批工作。
4. 启用版本后选择职位并显式确认正式运行。
5. 运行在人工节点暂停；HR 通过/跳过，失败节点可显式重试。
6. 可暂停、恢复或取消；事件、步骤和任务保留审计链。

## 页面详细设计

### 应用 Shell

- 左侧 244px 深色模块栏，可折叠为 82px；底部显示本地服务状态。
- 顶部 64px 粘性导航；招聘模块依次显示招聘看板、作业台、结果中心、管理后台，并提供“切换模型”入口。
- 内容区最大宽度 1660px，桌面左右留白 34px。
- 用户菜单承载角色、“新增自定义模型”和退出；完整模型管理仍在招聘管理后台，避免用一个新增表单冒充管理页。
- “切换模型”点击后在按钮下方打开选择菜单：顶部说明当前模型；中部逐行展示已保存档案的名称、模型名和活动文字状态；底部提供唯一的“新增自定义模型”动作。选择另一档案后立即关闭菜单并以状态提示确认，不进入管理页面。
- 新增/编辑档案使用表单抽屉，字段依次为“配置名称、API 地址、模型名称、API Key”；主操作为“保存并切换”。已保存密钥只展示末四位且编辑时允许留空沿用。表单错误不清空输入，Escape/遮罩/关闭按钮可退出。

### 考勤页面组

- 看板：期间/部门筛选 → 4 个 KPI → 日趋势/部门对比 → 导入质量/待办；数字可下钻。
- 人员：顶部搜索和新增；主体为人员表格；宽弹窗承载主数据、银行和考勤配置。
- 导入：用 STEP 01/02 双面板表达文件与核算期间，主按钮触发同步处理；下方保留历史批次。
- 结果：批次选择与导出在页头，密集表格显示核算构成；人工调整用弹窗渐进披露。
- 异常：按待审核/全部分段，卡片同时展示前一天、当天、打卡文本和决策按钮。
- 规则：策略和标签分栏卡片，点击卡片编辑；说明强调策略、标签、权限互相独立。

### 招聘页面组

- 招聘看板：跨岗位全局摘要和工作分流，是首次进入招聘模块的默认页；会话内仍记住最后访问的招聘页面。`/recruitment` 必须渲染真实看板，不能把 `overview` 归一为结果中心的“需要处理”。
- 招聘作业台：保持单一路由，以 `step=context|standard|plan` 呈现三页向导。顶部步骤条显示“选择本次作业 → 招聘标准 → 执行方案”，当前页只承载一个任务；完成本步动作后进入下一页，Step 2/3 可返回上一步且保留岗位草稿。
- 招聘标准页复用考勤导入的桌面上传语言：大面积虚线区域同时支持拖入和点击选择，允许 DOC/DOCX/XLSX 多文件、单文件最大 25MB；逐文件展示成功/失败，部分失败不重传成功项。
- 执行前检查只在 Step 3 展示；4–8 项运行参数按方案显示，页面只有一个“开始执行”主按钮。步骤推进不自动触发正式运行，成功后留在当前页显示运行编号与结果中心入口。
- 结果中心：顶部提供岗位、运行、状态和时间筛选；默认优先“需要处理”，其余为“任务结果、候选人与简历、招聘进度”内部视图。业务结果在前，技术日志默认折叠。
- 管理后台：单一路由内以子导航切换“职位同步、BOSS 账号与浏览器、流程方案、模型管理、系统诊断”；根据角色隐藏未授权模块，API 仍是最终权限边界。
- BOSS 账号页采用状态驱动交互：Worker/CLI 全局阻塞在账号区域顶部持续显示；账号动作在当前账号内显示“排队 → 正在打开 → 等待扫码 → 正在确认 → 已连接”，并每 5 秒自动收敛。Worker 离线时不得制造无法执行的任务。
- 账号主动作随状态变化：浏览器停止时“打开登录窗口”，等待登录时“聚焦登录窗口”，风控时“打开验证窗口”，就绪后降级为次级“重新打开”；检查状态只在错误或状态过期时作为辅助动作。BOSS 密码不保存、不代填。
- 账号的 CDP 端口、隔离目录和可执行文件属于技术详情，默认折叠；业务状态、最近确认时间、原因和下一步必须在 3 秒内可见，并用文本而非仅颜色表达。
- 模型管理：以列表展示当前登录用户的所有模型档案，活动项显示“当前使用”；每项提供切换、编辑、测试连接，页头提供“新增自定义模型”。模型为空时解释用途并给出同一新增动作，不出现 Copilot 或未开放功能占位。
- 生命周期操作：账号、职位、流程和任务各自提供“当前 / 已归档”切换，不能用一个全局归档开关污染其他子模块或账号运行态。当前列表的归档、删除等低频动作进入行级次级操作；归档列表直接提供“恢复”。职位同步文案只使用“同步到系统/已同步职位”，“归档”专指从当前业务列表移除。
- 归档必须二次确认并说明保留范围；恢复不需要确认。账号归档保留隔离目录和历史任务，职位归档不会操作 BOSS 线上职位，流程归档保留版本与运行，任务归档保留事件和证据。仅流程草稿与模型配置使用“永久删除”，并明确不可恢复。
- 模型配置删除确认必须说明将擦除 API 地址和加密 Key；删除当前模型后，新 AI 任务等待配置，但已有任务使用冻结快照继续执行。
- 功能迁移采用组合而非复制：岗位文档和标准编辑组件进入作业台；候选人、流程、简历智能组件进入结果中心；账号、任务、画布和职位同步进入管理后台。

### 招聘工作区四态与反馈

- 作业台 Loading：分区局部骨架，开始按钮显示“正在检查运行条件”；Empty：无职位/账号时只展示对应解决入口；Error：错误贴近字段且保留输入；Success：显示运行编号、状态和结果中心链接。
- 结果中心 Loading：保留上次成功内容并局部刷新；Empty：提供返回作业台；Error：区分局部数据失败、候选人失败和整次运行停止；Normal：人工事项置顶并支持筛选。
- 管理后台 Empty：按子模块引导添加账号、同步职位、定义方案或模型；浏览器未启动时只开放登录窗口恢复路径，其他动作明确阻塞原因。Worker 或 CLI 未就绪时不创建登录、同步或正式执行任务。
- 管理后台 Archived Empty：明确“暂无已归档记录”并提供返回当前列表；归档/删除失败必须保留原记录和确认上下文，不能显示成功或误清空列表。
- 模型选择 Loading：菜单保留轮廓并显示“正在读取模型”；Empty：只显示“尚未配置模型”和新增动作；Normal：当前模型有文字与勾选双重标识；Error：保留上次成功列表并提供重试。切换期间只禁用模型菜单，不阻塞当前业务页。

## 四态设计

| 页面组 | Loading | Empty | Normal | Error |
|---|---|---|---|---|
| 登录/Shell | 品牌呼吸标记 | 不适用 | 登录表单/应用壳 | 表单内错误 |
| 两个看板 | 首次加载变量，当前多为内容延迟出现 | 引导导入或连接账号 | KPI、任务、图表 | 页面错误 + 重试/保留导航 |
| 列表/表格 | 禁用动作或暂不渲染行 | 跨列空行 + 下一步文案 | 筛选、表格、详情 | 顶部错误条 |
| 文件/自动化 | 主按钮进行中文案、状态轮询 | 引导上传/添加账号/创建批次 | 状态徽标 + 时间线 | 可读错误、等待人工、显式重试 |
| 弹窗/抽屉 | 保存按钮禁用和“保存中” | 局部无记录提示 | 可编辑表单/证据 | 表单错误不关闭上下文 |

观察：现有页面普遍覆盖 Empty/Normal/Error，Loading 的视觉反馈不统一，除应用启动外缺少骨架；建议后续统一为局部骨架，避免整页跳变。

## 视觉规范

### 色彩

| Token | 色值 | 用途 |
|---|---|---|
| Ink | `#0F172A` | 主文字、主按钮、深色卡 |
| Slate | `#334155` | 次级标题与图标 |
| Muted | `#64748B` | 说明文字 |
| Line | `#E2E8F0` | 边框与分隔 |
| Paper | `#FFFFFF` | 面板 |
| Canvas | `#F3F6F8` | 页面背景 |
| Teal | `#0F9F8F` | 品牌、成功、选中、链接 |
| Teal dark | `#087F73` | 悬停与强调 |
| Amber | `#D97706` | 待处理/额度提醒 |
| Red | `#DC4A4A` | 错误/风险/危险动作 |

### 排版

- 字体：Inter、PingFang SC、Microsoft YaHei、system-ui。
- 页面标题 27px / 负字距；卡片标题 15px；正文 13px；辅助 9–11px。
- 英文 eyebrow/panel-kicker 使用 9–10px、粗体、0.11–0.15em 字距，仅作层级标记。
- 数字 KPI 29–31px，使用高字重与紧字距。

### 风格参数

- 4px 为隐含基础单位；常见间距 8/12/16/22/28/34px。
- 面板圆角 14–15px，按钮 9px，输入 9px，品牌标记 13–18px。
- 阴影克制：普通面板仅 `0 1px 2px rgba(...)`；主按钮和悬停卡片使用柔和抬升。
- 无外部 UI 框架，主题自定义程度高；组件语义由全局 CSS 类维护。

## 动效规范

### 基调

低到中等动效，以状态反馈和层级变化为主，不做装饰性页面转场。

| 场景 | 时长/缓动 | 现有行为 |
|---|---|---|
| 文字/边框悬停 | 150–180ms ease | 导航、链接、卡片 |
| 侧栏折叠 | 250ms ease | Grid 列宽过渡 |
| 指标条/趋势柱 | 450–500ms ease | 宽度/高度变化 |
| 弹出菜单 | Transition 类 | 透明度/位移 |
| 启动加载 | 1.2s ease-in-out 循环 | 品牌呼吸 |

建议尊重 `prefers-reduced-motion`；轮询结果只更新受影响卡片，不闪烁整页。

## 响应式策略

- ≥1200px：完整侧栏；作业台主表单 + 右侧粘性摘要，结果保持高信息密度，后台使用左侧子导航。
- 768–1199px：侧栏默认折叠；作业台单列、摘要移到顶部，结果筛选折叠为一行。
- <768px：侧栏变顶部/抽屉导航；作业台步骤纵向、主操作固定在可见区域，结果表格转卡片/保留必要横向滚动；流程画布仅查看并提示桌面编辑。
- 当前代码已有多处媒体查询和表格滚动；[待确认] 尚无真实移动设备验收证据。

## 数据需求汇总

| 页面 | 数据 |
|---|---|
| Shell | 当前用户、角色、登录状态、Worker/本地服务状态 [部分静态] |
