# 招聘作业台三页向导迭代计划

> 日期：2026-08-26
> 状态：设计已确认，实施中
> 范围：前端交互与文档；复用现有岗位文档和 Workflow API

## 目标

把招聘作业台从三段同屏长表单改为同一路由三页向导，并把岗位依据入口改为与考勤导入一致的拖拽上传体验。

## 交互契约

1. `step=context`：选择职位与对应 BOSS 账号，完成本步后进入招聘标准。
2. `step=standard`：上传 DOC/DOCX/XLSX 岗位依据并填写核心要求、加分项；点击“保存并继续”后进入执行方案。
3. `step=plan`：选择方案和运行参数，查看实时执行前检查，并显式点击“开始执行”。
4. Step 2/3 提供“上一步”；浏览器前进/后退与刷新恢复当前步骤和岗位草稿。
5. 文件支持点击或拖拽多选，单文件最大 25MB；客户端先提示空文件、扩展名和大小，服务端继续作为最终校验边界。
6. 上传保持顺序逐文件请求，部分失败保留成功项，不隐式重试结果不确定的文件。
7. 步骤完成后只自动切换页面，绝不自动创建 WorkflowRun 或触发任何 BOSS 动作。

- [ ] 增加步骤状态、URL 同步、前置守卫、焦点与可访问步骤条。
- [ ] 增加按用户和岗位隔离的版本化会话草稿。
- [ ] 重构文件处理为点击/拖拽共用的顺序上传队列与逐文件反馈。
- [ ] 把三个内容区改为单页条件渲染；执行检查与回执仅放最终页。
- [ ] 更新作业台定向测试，覆盖步骤、历史、草稿、上传边界和既有执行幂等。
- [ ] 运行前端全测、生产构建和浏览器旅程验收。

## 非目标

- 不新增后端端点、模型、迁移或依赖。
- 不把未上传的 File 对象写入浏览器存储。
- 不改变职位权限、岗位文档归档、流程审批、额度、身份复核或幂等规则。

## 验收标准

- 首屏只显示一个 Step，用户可在 3 秒内理解当前位置与下一步。
- 合法前置条件下可顺序进入三个页面，后退不丢字段；非法深链回到可访问步骤并说明原因。
- 点击和拖拽都能上传多个合法文件；错误文件不请求后端，部分失败可再次选择且不重传成功项。
- 主动寻访缺核心要求时最终页明确引导返回 Step 2。
- 正式执行成功、失败恢复、双击防重和结果中心深链保持原契约。
