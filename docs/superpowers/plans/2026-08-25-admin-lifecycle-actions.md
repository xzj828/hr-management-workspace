# 管理后台生命周期操作迭代计划

日期：2026-08-25

## 问题

招聘管理后台重组时只迁移了新增、编辑和执行动作，旧页面已有的账号、职位、流程与任务归档/恢复没有进入新页面；模型档案缺少按档案删除 API。同时账号、职位和流程模板仍继承通用物理 DELETE，可能绕过领域审计或级联删除历史证据。

## 产品契约

- BOSS 账号、职位、流程模板、自动化任务：归档/恢复，不物理删除。
- 流程版本：只有未启用、非活动且没有运行记录的草稿可以永久删除。
- 模型档案：允许永久删除并擦除加密 Key；删除活动档案同时清除活动投影，不自动切换到其他档案。
- 各管理子模块独立提供“当前 / 已归档”，避免一个全局开关影响其他模块和账号轮询。
- 归档/删除先确认；恢复直接执行。失败保留原记录并显示服务端原因。

## 实施任务

1. [x] 收紧后端物理删除边界，补模型档案 DELETE 和流程草稿运行记录冲突。
2. [x] 扩展前端模型 store 的并发安全删除与状态对账。
3. [x] 在管理后台迁入账号、职位、流程、任务的归档/恢复及模型/草稿删除。
4. [x] 补 API、store、组件和管理后台回归测试。
5. [x] 执行后端、前端、构建、迁移漂移与独立对抗审查。

- 后端 accounts + recruitment 全量 389/389 通过；生命周期与模型新增回归通过。
- 前端全量 39 文件 193/193 通过；生产构建通过。
- 独立技术审查：功能 9/10、健壮性 8/10、最小改动 9/10、代码质量 8/10，P0/P1 为 0，PASS。
- 后续可访问性复审指出的焦点圈、处理中关闭、归档错误态、流程草稿归档和任务截断均已补齐并增加回归。

## 验收标准

- 账号、职位、流程模板的 detail DELETE 返回 405，生命周期只能走归档服务。
- 活动任务关联账号、活动任务本身归档返回可读 409；成功归档保留历史证据并可恢复。
- 有运行记录的流程草稿删除返回 409，不产生 ProtectedError/500。
- 模型档案删除按用户隔离，活动档案删除同步移除兼容投影，响应不泄漏密钥，已绑定 AI 任务继续使用快照。
- 管理后台每个相关标签页能在当前与已归档记录间切换；成功后对象立即从当前列表移除，恢复后回到当前列表。
- 所有确认、失败和空态文案区分“归档”与“永久删除”，职位同步不再称为生命周期归档。
