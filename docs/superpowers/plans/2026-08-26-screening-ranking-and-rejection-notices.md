# 候选排名、人工初筛与未通过通知实施计划

> 状态：已完成并验收
> 日期：2026-08-26
> 范围：结果中心“候选人与简历”、人工初筛结论、批量未通过通知

## 产品目标

HR 在一个结果页完成“查看当前排名 → 核对原始简历与分析报告 → 确认通过/未通过 → 对未通过候选人创建通知队列”。AI 只提供证据化建议，不能代替 HR 决策或自动外发。

## 已确认契约

- 排名只使用当前未归档简历、最新结构化版本和当前已发布岗位标准下的最新评分；旧版本不参与。
- 全部应聘都显示。未评分、处理中、失败和无简历排在末尾，`rank=null`，不能作为零分或未通过。
- AI 建议、HR 决策、招聘阶段、通知状态四列独立。
- HR 决策只追加且版本化，绑定当时简历/评分，不修改 Application stage。
- 未通过通知使用独立 `rejection_notice` 动作；准备冻结快照，批准时整批校验额度并一次性物化任务。
- Worker 只允许平台稳定 ID 原子定位、复核和发送；当前适配器缺少能力时必须 `waiting_human`，不按姓名回退。

## 验证结果

- 排名、人工结论、通知审批/额度/身份/隐私与并发回归纳入招聘域 417 项测试。
- 前端排名、详情懒加载、批量选择、人工结论和通知抽屉纳入 243 项全量测试；生产构建通过。
- `recruitment.0028` 已实际应用；当前适配器缺少稳定 ID 原子发送能力时继续转人工提醒，不按姓名回退。

## 验收标准

1. 当前标准 V1 不会被旧标准 V5 或旧简历高分覆盖，排序平分稳定。
2. 通过、建议未通过、待复核、未评分、已淘汰流程记录均可见且语义不混淆。
3. 点击候选人在结果中心查看原件、结构化信息、评分证据和历史；刷新/返回保持深链语义。
4. 批量决策幂等、整批鉴权，且不自动改变招聘阶段或发送消息。
5. 通知只接受最新人工未通过结论；额度不足不产生部分任务；重复批准不重复扣额。
6. 无稳定平台 ID、错误 ID、同名或适配器能力缺失时不调用姓名发送，逐项进入人工介入。
7. 决策与通知状态分离；部分失败可见，成功项不重复，不确定结果不自动重试。
8. Viewer/跨账号/跨岗位均失败关闭；响应、日志和测试快照不泄露完整平台身份或通知敏感内容。
9. 桌面、窄屏、键盘、焦点、Escape、颜色非唯一表达通过验收。
