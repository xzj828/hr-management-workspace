# BOSS 招聘自动化第一阶段设计

日期：2026-08-24
状态：已由用户逐段确认，待文档复核

## 1. 目标

把现有“BOSS 账号登录检查与职位只读同步”扩展为一套以人工确认、批量执行、可恢复和可审计为核心的招聘自动化工作台。

第一阶段需要完成：

- 从 BOSS 推荐、常规搜索和深度搜索发现候选人；
- 将 HR 勾选的候选人同步到本地候选人库；
- 人工确认后批量打招呼、索要简历和发送面试邀约；
- 下载候选人发送的附件简历，并在人工确认后保存在线简历 PDF；
- 根据自动化结果推进招聘流程，并允许 HR 手动纠正；
- 提供可拖拽但受规则约束的招聘流程画布；
- 在多 BOSS 账号环境下防止重复联系、并发冲突和误操作。

系统以功能结果和长期稳定性为优先，不强制所有页面动作都经过 `boss-cli`。

## 2. 第一阶段边界

### 2.1 纳入范围

- BOSS 账号隔离浏览器、登录检测和人工验证；
- 点击“同步职位”后自动完成一次完整职位同步；
- 推荐候选人、关键词搜索和深度搜索；
- 候选人发现池、批量勾选、正式入库和重复检测；
- 打招呼、索要附件简历和结构化面试邀约；
- 附件简历下载、在线简历 PDF 保存、预览、下载和版本管理；
- 候选人沟通状态同步；
- 招聘阶段自动推进、人工调整和审计；
- 受控流程画布、人工确认队列、执行批次和失败恢复；
- 真实数据与演示数据隔离。

### 2.2 暂不实现

- AI 简历评分和智能筛选，只保留 Copilot 页面及扩展接口；
- 开放式自动聊天、复杂上下文回复和无人值守谈判；
- 在 BOSS 自动创建、修改、发布或关闭职位；
- 任意脚本节点、无限循环或绕过人工确认的自由流程；
- 后台定时职位同步。

职位发布能力只保留扩展位置。当前流程为 HR 在 BOSS 发布职位后，在工作台点击“同步职位”，系统自动读取并更新本地职位。未来如实现职位发布，优先采用自动填写、HR 最终确认的半自动模式。

## 3. 核心原则

1. 所有会向候选人发送内容或消耗平台次数的操作，必须先由 HR 确认。
2. 系统不绕过验证码、安全验证、扫码、风控或平台限制。
3. 同一 BOSS 账号任何时刻只允许一个浏览器执行器控制。
4. 每位候选人独立执行和记录，一个失败不能中断整个批次。
5. 自动化成功后才改变招聘阶段，失败或结果不确定时维持原状态。
6. 页面身份校验失败时禁止发送，不能依赖姓名模糊匹配直接执行写操作。
7. 业务后端不依赖具体浏览器实现，BOSS 页面变化只影响自动化适配层。

## 4. 总体架构

```text
Vue 3 招聘工作台
├─ 职位管理与一键同步
├─ 候选人库 / 发现候选人
├─ 招聘流程看板
├─ 简历中心
├─ 人工确认队列
└─ 受控流程画布
          ↓
Django 招聘业务 API
├─ 职位、候选人、简历和面试邀约
├─ 流程模板、执行批次和步骤
├─ 权限、配额、去重和审计
└─ 自动化能力统一接口
          ↓
自动化编排器与 Windows Worker
├─ 账号级队列与进程锁
├─ 暂停、恢复、重试和人工接管
├─ BOSS CLI 适配器
└─ Playwright/CDP 适配器
          ↓
Chrome / Edge 独立持久浏览器目录
          ↓
BOSS 直聘招聘者页面
```

Django 只描述业务意图和状态，不直接运行长时间浏览器任务。Windows Worker 领取白名单任务，并通过统一适配层选择 CLI 或 Playwright/CDP。

## 5. 混合自动化适配层

### 5.1 CLI 优先能力

现有 `@joohw/boss-cli 0.6.6` 已提供登录、职位读取、聊天列表、会话打开、推荐、常规搜索、深度搜索、简历预览、打招呼、发送文本和索要简历等命令。经过真实账号回归验证且输出足够稳定的动作优先复用 CLI。

### 5.2 Playwright/CDP 能力

以下场景允许由项目内 Playwright/CDP 实现：

- CLI 输出不足以形成结构化候选人档案；
- 检测、下载和校验聊天附件；
- 将在线简历保存为 PDF；
- 填写结构化面试邀约；
- 执行前核验候选人身份和页面上下文；
- 保存关键结果截图和诊断信息。

CLI 与 Playwright 共用账号隔离浏览器目录和 CDP 端口，但必须通过同一账号锁串行执行。业务 API 只调用统一能力名称，不感知底层实现。

### 5.3 能力注册表

每项能力记录实现方式、版本、是否只读、是否消耗次数、是否需要人工确认和是否支持重试。适配器启动时完成能力探测，不支持的操作在前端明确禁用，不能伪装成功。

## 6. 职位同步

职位管理页面提供“同步职位”操作：

1. HR 选择 BOSS 账号并点击同步；
2. 系统创建只读同步任务；
3. Worker 读取该账号全部职位；
4. 以 BOSS 账号和外部职位标识执行新增或更新；
5. 返回新增、更新、关闭和未变化数量；
6. 职位绑定发现它的 BOSS 账号，并可配置默认操作账号。

系统不进行后台定时同步，也不修改 BOSS 上的职位。HR 需要最新结果时主动点击按钮。

## 7. 候选人发现与入库

“候选人”页面包含两个页签。

### 7.1 候选人库

保存已正式进入招聘流程的候选人，支持按职位、阶段、负责人和关键词筛选。候选人详情展示基本资料、来源、沟通记录、招聘阶段和简历 PDF。

### 7.2 发现候选人

HR 先选择 BOSS 账号、职位和发现方式：

- 推荐候选人；
- 关键词常规搜索；
- 深度搜索。

深度搜索中的“立即匹配”会消耗次数，必须单独确认。搜索结果先进入临时发现池，不直接污染正式候选人库。

每条结果显示平台展示名、当前职位、城市、工作年限、学历、候选人优势、技能标签、来源职位、来源入口和最近同步时间。联系方式仅在候选人主动提供或简历中存在时保存。

HR 可以勾选一人或多人，执行：

- 加入候选人库；
- 加入候选人库并打招呼。

加入或打招呼成功后，记录从发现池移入候选人库。单击候选人可打开详情；查看在线简历前再次提示可能消耗查看次数。

### 7.3 去重规则

- 同一账号优先使用 BOSS 候选人稳定标识去重；
- 跨账号使用可验证的平台标识或多字段指纹辅助发现重复；
- 同一候选人已经被任一账号联系时，其他账号默认禁止再次打招呼；
- HR 可以在确认面板中更换账号，但系统必须展示已有联系记录并阻止确定性重复发送；
- 姓名相同不能直接认定为同一候选人，也不能作为写操作的唯一定位条件。

## 8. 简单沟通与人工确认

第一阶段仅支持三种对外沟通：

1. 打招呼；
2. 索要附件简历；
3. 发送面试邀约。

话术使用可编辑模板，不接入复杂对话 Agent。面试邀约由结构化表单生成，字段包括面试时间、线上或线下、地址或会议链接、联系人和备注，暂不接日历或会议平台。

所有发送动作先进入人工确认队列。确认面板展示账号、职位、候选人、最终话术、预计消耗和重复联系提示。HR 可以逐条修改、排除候选人或取消整批操作。确认后才创建执行批次，确认时的内容作为不可变快照保存。

## 9. 简历获取与管理

### 9.1 附件简历

系统读取已建立联系的会话，检测候选人发送的附件。发现新附件后下载到本地受控存储，计算文件校验值，关联候选人和职位，并记录来源、原文件名、内容类型和获取时间。相同文件不得重复保存。

### 9.2 在线简历

在线简历查看次数有限，不允许后台批量打开。HR 点击并确认“查看在线简历”后，系统打开对应候选人、核验身份、读取在线简历并保存为 PDF。若页面无法稳定导出，任务必须失败并保留诊断，不生成伪 PDF。

### 9.3 工作台入口

候选人详情和简历中心均提供：

- 工作台内 PDF 预览；
- 下载 PDF；
- 多版本列表；
- 文件来源、获取时间和处理状态；
- 缺失文件、下载失败和页面变化的明确提示。

AI 评分状态显示为“待功能开放”，不执行模型调用。

## 10. 招聘阶段推进

自动化事件与阶段映射：

```text
发现并正式入库      → 新候选人
打招呼成功          → 已打招呼
检测到候选人回复    → 沟通中
索要简历成功        → 待简历
附件或在线简历归档  → 已收简历
HR 提交人工筛选      → 待面试或已淘汰
面试邀约发送成功    → 待面试
HR 确认进入面试      → 面试中
```

自动化结果不确定或失败时不推进阶段。HR 可以手动修改阶段，但必须填写或选择原因。每次变化保存操作者、来源任务、前后阶段、时间和原因。

## 11. 受控流程画布

流程画布允许拖拽、连线、保存、复制、启用和停用，但只开放经过验证的节点：

- 读取推荐；
- 常规搜索；
- 深度搜索；
- 人工筛选；
- 加入候选人库；
- 人工确认；
- 打招呼；
- 等待回复；
- 索要简历；
- 等待简历；
- 人工复核；
- 发送面试邀约；
- 结束。

系统禁止无候选人来源、无账号、无人工确认的发送节点，禁止循环连线、并行控制同一账号和任意脚本。流程可以跨天等待；启用中的流程版本不可原地覆盖，修改后生成新版本。

## 12. 执行模型与恢复

一个 HR 确认动作生成一个执行批次，每位候选人生成独立步骤实例。步骤状态为：

```text
待确认 → 待执行 → 已领取 → 执行中 → 核验中 → 成功
                                      ├→ 等待人工
                                      ├→ 失败
                                      ├→ 已跳过
                                      └→ 已取消
```

写操作使用幂等键，至少包含账号、候选人、动作类型和确认快照。Worker 崩溃或浏览器关闭后，系统先核验 BOSS 当前状态，再决定恢复或转人工，不能直接重复发送。

触发验证码、扫码、风险验证、页面身份不一致或无法确认发送结果时，暂停当前账号的后续写任务。HR 完成验证后点击“继续检查”，编排器从安全检查点恢复。

## 13. 数据模型

在现有 `BossAccount`、`RecruitmentJob`、`Candidate`、`JobApplication`、`Resume`、`RpaTask` 和审计模型基础上新增或扩展：

- `CandidateDiscovery`：临时发现结果、搜索条件、来源和过期时间；
- `CandidateExternalIdentity`：账号、平台标识、候选人及去重指纹；
- `ConversationAction`：动作、话术快照、确认人、执行结果和外部证据；
- `ResumeAsset`：文件、校验值、来源、版本和获取状态；
- `InterviewInvitation`：结构化邀约内容和发送状态；
- `WorkflowTemplate`、`WorkflowVersion`、`WorkflowNode`、`WorkflowEdge`；
- `ExecutionBatch`、`StepExecution` 和 `HumanApproval`；
- `AutomationEvidence`：关键截图、页面标识和脱敏诊断。

发现池数据设置保留期限；转为正式候选人后保留业务所需字段。真实数据、演示数据和测试数据使用明确标记和独立清理入口。

## 14. 权限、隐私和配额

- 用户只能查看和操作被授权的 BOSS 账号；
- Cookie、浏览器缓存和登录态只存在本机账号隔离目录，不写入 Django 数据库；
- 下载、预览和删除简历均写入审计日志；
- 自动化证据不保存 Cookie、令牌、完整手机号或其他不必要敏感值；
- 账号支持每日打招呼、消息、深度匹配和简历查看上限；
- 达到上限后停止创建相关步骤，不能靠重试绕过；
- 清除候选人时同步清理不再被引用的本地 PDF；
- 账号所有者负责确认其使用方式符合平台规则和适用要求。

## 15. UI 与交互

保留左侧深色模块栏和内容区顶部导航。视觉使用当前墨绿主色、柔和浅灰背景、白色圆角卡片和同一套本地线性 SVG，不增加手机端布局。

候选人发现页使用筛选条与轻量候选人卡片列表。勾选后底部批量操作栏浮入；候选人详情和人工确认从右侧滑出。招聘流程使用低分割感看板，流程编排使用浅色网格画布、左侧节点库和右侧属性面板。

主要动效：

- hover 和选中反馈为 120–160ms；
- 菜单和提示为 160–200ms；
- 抽屉和批量操作栏为 200–260ms；
- 拖拽目标实时高亮并使用轻微弹性回落；
- 页面数据更新不整页闪烁，使用局部骨架和明确阶段进度；
- 支持系统“减少动态效果”设置，不使用干扰阅读的循环动画。

批量任务展示“等待执行、打开浏览器、定位候选人、执行动作、核验结果、完成”等阶段。面板可收起，单个候选人失败不会阻塞其他项。

## 16. 错误处理

统一错误分类至少包括：

- CLI 缺失、版本不兼容或命令失败；
- 浏览器未启动、目录被占用或 CDP 不可用；
- 登录失效、二维码失效、验证码和风险验证；
- 页面结构变化、候选人身份不一致或目标元素缺失；
- 平台次数不足、账号限制或操作不允许；
- 附件下载失败、文件类型异常或 PDF 生成失败；
- 网络超时、结果不确定和 Worker 崩溃。

错误记录面向 HR 显示可执行的中文说明，面向开发保留脱敏诊断、适配器版本和关键截图。结果不确定的写操作只能转人工核验，不能自动重试。

## 17. 测试与验收

### 17.1 自动化测试

- 权限、账号隔离、配额和去重；
- 人工确认快照、流程校验和阶段推进；
- 批次部分失败、暂停、恢复、取消和幂等；
- CLI 与 Playwright 适配器契约；
- 固定 HTML 样本的页面解析和结构变化检测；
- 附件去重、PDF 预览、下载和文件清理；
- Vue 勾选、抽屉、批量确认、看板和流程画布交互；
- 原有考勤、登录和招聘基础能力回归。

### 17.2 真实账号验收

默认使用演练模式，只读取和生成待确认项。发送类验收由 HR 指定测试候选人并再次确认。

必须验证：

1. 同一候选人不会重复联系；
2. 页面错位时不会向错误候选人发送；
3. 浏览器中断后任务能够安全恢复或转人工；
4. 验证码和风控出现时账号后续任务立即暂停；
5. 批量任务部分失败不会重复执行已成功项；
6. 附件和在线简历 PDF 正确关联、预览和下载；
7. 自动与手动阶段变化均可追溯；
8. 多账号之间的浏览器目录、端口、队列和配额完全隔离。

## 18. 建议交付顺序

1. 扩展任务模型、统一能力接口、确认队列、幂等和账号配额；
2. 完成职位一键同步结果反馈和候选人发现池；
3. 接入推荐、常规搜索、深度搜索和候选人结构化同步；
4. 完成候选人库、批量勾选、去重和打招呼确认队列；
5. 完成会话状态、索要简历、附件下载和 PDF 管理；
6. 完成结构化面试邀约和招聘阶段自动推进；
7. 完成受控流程画布、跨天等待和恢复；
8. 完成视觉动效、错误诊断、真实账号演练和回归验收。

每一批都先完成自动化测试和演练模式验收，再开启下一批真实写操作。
