# BOSS 招聘自动化流程运行引擎设计

日期：2026-08-24

## 目标

将现有“可绘制、可保存、可启用”的流程编排器补全为可执行的受控 DAG 引擎。HR 可以自定义合法节点间的连接关系、配置节点参数、试运行或正式运行流程，并在人工节点暂停后确认继续。所有真实 BOSS 外发继续遵循人工确认和幂等防重规则。

## 编排器能力

### 节点与连接

- 每个节点明确显示左侧输入端口和右侧输出端口。
- HR 从一个节点的输出端口拖线到另一个节点的输入端口，建立自定义连接。
- 节点和连线均可选中、删除和重新连接。
- 支持一个节点连接多个后继节点，但第一版不提供条件表达式；多个后继按稳定顺序依次调度。
- 支持多个上游汇入同一节点；该节点在所有已激活上游完成后执行。
- 禁止自连接、重复连接和循环连接。
- 删除节点时同步删除关联连线，并在保存前显示影响提示。

### 节点配置

选中节点后在画布右侧打开配置面板。不同节点提供对应字段：

- 推荐/搜索：BOSS 账号、职位、关键词、候选人数量上限。
- 人工筛选/人工复核：负责人、提示说明、最长等待时间。
- 人工确认：待确认动作摘要和确认人。
- 打招呼/索要简历：消息模板、候选人批次上限。
- 等待回复/等待简历：等待时长、超时后的处理方式。
- 面试邀约：时间、形式、地点、联系人模板；正式执行前仍允许 HR 修改。
- 结束：完成原因和运行结果标签。

配置随流程版本保存。启用版本不可原地修改，基于历史版本重新编排后生成新版本。

## 运行方式

### 试运行

试运行验证节点配置、连接关系、账号状态、职位范围和预计候选人数。它可以执行只读搜索并生成候选人预览，但不会发送消息、消耗简历查看额度或改变候选人阶段。发送类节点显示模拟结果“等待人工确认（试运行未发送）”。

### 正式运行

正式运行前展示确认摘要：流程版本、执行账号、职位、候选人范围、可能发送的动作和配额。HR 确认后创建不可变运行快照，之后按 DAG 顺序执行。

发送节点不能直接调用 BOSS：运行到发送节点时创建现有 `AutomationApproval`、`ExecutionBatch` 和逐候选人 `StepExecution`。只有审批通过后才进入 RPA Worker 队列。已成功候选人使用幂等键防止重复发送。

### 运行状态

流程运行状态：`pending`、`running`、`waiting_human`、`paused`、`succeeded`、`failed`、`cancelled`。

节点运行状态：`pending`、`ready`、`running`、`waiting_human`、`succeeded`、`skipped`、`failed`、`cancelled`。

运行页面实时显示当前节点、已完成节点、等待人工事项、候选人处理数量、失败原因和最近更新时间。

## 调度语义

- 来源节点创建本次运行的候选人集合。
- 普通节点在所有已激活上游成功或跳过后进入 `ready`。
- 人工节点进入 `waiting_human`，HR 可批准继续、拒绝并终止或跳过允许跳过的节点。
- 多后继节点按保存时的边顺序调度；每个后继接收相同的运行上下文。
- 汇合节点等待全部已激活上游结束，不等待没有被激活的路径。
- 节点失败默认停止其下游，并把运行标记为失败；允许重试的只读节点可由 HR 手动重试。
- 暂停不终止正在执行的单个 RPA 操作，但阻止后续节点开始。
- 终止会取消未开始节点和可取消的排队任务，已成功的真实操作不会回滚。

## 数据模型

新增：

- `WorkflowRun`：流程版本、模式、状态、账号、职位、启动人、不可变运行快照、统计与时间。
- `WorkflowNodeRun`：节点快照、状态、输入输出、错误、重试次数与时间。
- `WorkflowRunEvent`：运行级审计时间线。

现有 `AutomationApproval`、`ExecutionBatch`、`RpaTask` 和 `StepExecution` 通过外键或稳定标识关联到节点运行，不重复实现消息安全逻辑。

## API 与前端

API 提供：创建试运行、创建正式运行、运行详情、暂停、继续、终止、人工节点决策和允许节点重试。所有写入使用事务和幂等请求标识。

编排工作区增加：

- 顶部“试运行”和“正式运行”入口。
- 右侧节点配置面板。
- 运行前确认抽屉。
- 运行详情面板和节点状态覆盖层。
- 最近运行列表及暂停、继续、终止入口。

没有启用版本、账号未登录、缺少职位、节点配置不完整或流程图无效时，运行按钮禁用并显示具体原因。

## 安全与故障处理

- 所有发送节点必须存在人工确认祖先，且运行时再次人工确认。
- 同账号、候选人、职位、动作和流程运行生成稳定幂等键。
- Worker 重启后从数据库恢复未完成运行；过期任务由统一租约回收逻辑处理。
- 单个候选人失败不会重复执行同批次已成功候选人。
- BOSS 登录失效时节点进入 `waiting_human`，账号状态同步显示需要重新登录；登录恢复后 HR 可继续运行。
- 取消和失败均写入审计事件，不删除历史运行数据。

## 测试与验收

- 图校验测试：自定义连接、删除、重连、分支、汇合、循环和重复边。
- 调度测试：线性流程、分支、汇合、人工暂停、继续、失败、重试和终止。
- 安全测试：试运行不外发、正式运行必须审批、幂等防重、配额和跨账号隔离。
- 恢复测试：Worker 重启、过期租约、登录失效后继续。
- 前端测试：端口拖线、节点配置、运行按钮状态、确认抽屉和实时运行状态。
- Edge 浏览器验收：保存并启用流程、试运行、正式运行至人工确认节点、取消而不产生真实发送。

完成标准：HR 能从画布连接任意合法节点，配置并保存新版本；试运行完整走通且不外发；正式运行按连线执行并在人工节点安全暂停；运行状态、错误、暂停、继续和终止均可见且有审计记录。
