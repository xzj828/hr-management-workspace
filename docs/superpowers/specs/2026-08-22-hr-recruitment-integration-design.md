# 西鸣人事管理系统：招聘与考勤整合设计

日期：2026-08-22  
状态：已由用户确认，待书面复核

## 1. 目标

将现有“西鸣考勤管理系统”升级为统一的“西鸣人事管理系统”。系统保留现有 Vue 3 视觉风格和考勤能力，新增完整招聘管理模块，并以 `boss-cli` 作为 BOSS 直聘浏览器 RPA 执行引擎。

系统应覆盖以下招聘闭环：

```text
候选人获取
→ 沟通与简历
→ 人工筛选
→ 面试
→ Offer
→ 录用
→ 转入人员管理
```

压缩包 `BossHiringWorkspace-code-20260822-151932(1).zip` 中的 FastAPI 代码只作为业务行为参考，不直接复制。压缩包内约 314 条候选人记录、6 份简历及评分报告属于其他公司数据，不迁移、不初始化、不用于本项目测试。

## 2. 非目标

- 不使用 Django 渲染前端页面；前端继续使用 Vue 3。
- 不直接照搬原招聘工作台的单文件 FastAPI 后端。
- 不让 RPA 或大模型自主淘汰、录用或发送 Offer。
- 不把姓名作为候选人的稳定唯一身份。
- 不在第一期实现真实的大模型简历分析后端，但会完成前端 Demo 和接口契约。
- 不支持在 macOS 上执行 RPA；RPA 统一运行在 Windows。

## 3. 总体架构

```text
Vue 3 人事管理前端
        ↓
Django 统一业务后端
├─ attendance：现有考勤模块
├─ recruitment：招聘业务模块
├─ accounts：账号、角色与权限
├─ automation：任务队列、Worker 状态与审计
└─ copilot：模型配置和未来模型调用契约
        ↓
数据库与本地文件存储
        ↓
Windows RPA Worker
        ↓
boss-cli → 独立 Chrome 配置 → BOSS 直聘
```

Django 和 Windows RPA Worker 第一阶段运行在同一台 Windows 电脑上，但二者保持进程隔离。浏览器或 CLI 卡死不得阻塞考勤 API 和普通招聘页面。

## 4. 信息架构

系统品牌修改为“西鸣人事管理系统”。

### 4.1 顶部业务导航

```text
招聘管理 | 考勤管理
```

顶部导航只负责切换业务域。左侧导航根据当前业务域切换，避免将所有功能平铺在顶部。

### 4.2 招聘管理左侧导航

```text
招聘看板
职位管理
候选人
招聘流程
自动化任务
简历中心
```

沟通与待办并入候选人详情和招聘看板；面试、Offer、录用并入招聘流程；招聘设置位于侧栏底部的系统设置区域；Copilot 通过招聘页面右上角入口或侧边抽屉打开，不单独占用导航项。

### 4.3 考勤管理左侧导航

```text
考勤看板
人员管理
导入中心
核算结果
异常审核
规则与标签
```

现有考勤路由和页面能力保持兼容。

## 5. 招聘业务设计

### 5.1 招聘阶段

```text
新候选人
→ 待联系
→ 已打招呼
→ 沟通中
→ 待简历
→ 已收简历
→ 待筛选
→ 待面试
→ 面试中
→ 待 Offer
→ 已录用 / 已淘汰 / 人才库
```

阶段变化必须写入历史记录，包含操作者、时间、原阶段、新阶段和原因。自动化执行可以推进到“已打招呼”“待简历”“已收简历”，但淘汰、Offer 和录用必须由有权限的人员确认。

### 5.2 招聘看板

看板展示在招职位、今日新增候选人、待联系、待回复、待收简历、待面试、今日联系额度、职位进度、阶段转化率、逾期未跟进、自动化失败、BOSS 登录和风控状态。

### 5.3 职位管理

职位支持从 BOSS 同步，也允许系统内补充招聘负责人、部门、招聘人数、截止日期、搜索关键词、排除词、目标地区、联系额度、联系时间和话术模板。

### 5.4 候选人中心

候选人作为长期人才档案管理。候选人与职位之间使用独立应聘关系，支持一个候选人对应多个职位。候选人页面展示来源、阶段、负责人、标签、备注、最近互动、简历、面试、Offer 和完整时间线。

### 5.5 招聘流程

使用阶段看板呈现候选人。支持人工拖动阶段、批量分配负责人、创建面试、填写面试反馈、管理 Offer 和录用。录用后可创建现有 `Employee` 记录；若工号、电话或其他唯一字段疑似重复，必须要求人工确认，不能覆盖现有员工。

### 5.6 简历中心

支持图片、PDF、Word 和文本简历的归档、预览、下载、人工查看状态、人工结论和删除确认。简历必须绑定候选人和应聘职位，并记录来源、获取方式、获取时间和文件哈希，以避免重复保存。

## 6. 数据模型

新增主要实体：

- `BossAccount`：BOSS 账号配置、运行状态、浏览器配置标识、端口、额度和授权用户。
- `RecruitmentJob`：系统职位及对应的 BOSS 职位标识、JD、负责人和招聘配置。
- `Candidate`：候选人主体档案，不以姓名作为唯一标识。
- `JobApplication`：候选人与职位的应聘关系、来源、阶段、负责人和优先级。
- `CandidateStageHistory`：阶段变化审计。
- `CandidateInteraction`：外发消息、回复摘要、电话或人工沟通记录。
- `Resume`：简历文件、哈希、类型、解析状态和人工结论。
- `Interview`：面试时间、方式、面试官和状态。
- `InterviewFeedback`：面试官反馈。
- `Offer`：Offer 状态、预计入职日期和备注。
- `RpaTask`：一次自动化任务的总体状态。
- `RpaTaskItem`：任务中每个候选人或职位的执行状态和重试信息。
- `RecruitmentAuditLog`：招聘敏感操作审计。
- `UserModelCredential`：按用户加密保存的大模型 API 配置。

候选人身份优先使用 BOSS 提供的稳定外部 ID。没有稳定 ID 时，系统保存来源账号、来源职位、来源页面、卡片序号、原始字段指纹等组合身份，并在任何外发动作前重新核验页面目标。

## 7. 多 BOSS 账号与 Windows RPA

多个 BOSS 账号均运行在 Windows。每个账号必须拥有独立的：

- Chrome 用户数据目录；
- CDP 调试端口；
- 登录、验证码和风控状态；
- 职位及候选人来源；
- 串行任务队列；
- 每日联系额度和操作间隔。

同一账号严格串行。不同账号只有在浏览器目录和端口隔离后才允许并行，且受系统全局并发上限控制。第一期默认全局并发为 1，后续验证稳定后再提高。

Worker 只接受白名单动作：

```text
CHECK_STATUS
LOGIN
SYNC_POSITIONS
LOAD_JD
COLLECT_CANDIDATES
OPEN_CANDIDATE
GREET_CANDIDATE
SEND_MESSAGE
REQUEST_RESUME
SCAN_RESUME_INBOX
DOWNLOAD_RESUME
```

Worker 不接受任意 Shell 命令。每个动作返回统一的结构化结果、错误类别、可重试标志和脱敏日志。

## 8. 自动化安全与恢复

- 外发前展示账号、职位、候选人、人数和最终话术。
- 界面确认后才创建任务。
- 后端再次检查角色、账号授权、每日额度和任务状态。
- 设置单批上限、每日上限、最小操作间隔和失败退避。
- 检测登录失效、验证码、风控弹窗和页面结构异常，并立即暂停对应账号队列。
- 支持暂停、继续、取消和按失败项重试。
- 禁止在未核验身份时从严格匹配回退到模糊姓名发送。
- 保存操作者、目标、话术、执行时间、结果和错误。
- 任务恢复不得重复发送已成功的消息或重复下载同一简历。

## 9. 权限

- 系统管理员：全部权限、系统设置、BOSS 账号授权和模型配置管理。
- HR：职位、候选人、自动化任务、简历、面试、Offer 和录用。
- 部门主管：查看本部门职位与候选人，填写面试反馈，不能执行 BOSS 外发。
- 只读用户：仅查看，不允许修改阶段、下载敏感文件或执行自动化。

权限在 Django API 层强制执行，不能只依赖 Vue 按钮隐藏。

## 10. 简历筛选与 Copilot Demo

简历筛选采用：

```text
简历解析或 OCR
→ 去除与岗位无关的敏感信息
→ 大模型提取结构化证据
→ Django 校验 JSON 结构
→ 确定性规则引擎计算分数
→ HR 人工复核和最终决定
```

第一期完成前端 Demo、数据结构和 API 契约，不实现真实模型分析。页面支持模型 API 地址、API Key、模型名称、连接测试、职位/候选人/简历上下文以及候选人总结、JD 对照、面试问题、沟通话术和招聘摘要等快捷能力。

大模型不得使用性别、年龄、照片、婚育、籍贯、民族或与岗位无关的个人信息参与评分。简历未说明的硬性条件标记为“未知”，不得自动视为不满足。

## 11. API Key 与记住登录

### 11.1 API Key

API Key 按用户账号持久化保存，下次登录无需重新输入。安全要求：

- API Key 使用应用主密钥加密后存入 `UserModelCredential`，不得与用户密码字段混存。
- 数据库不得保存明文 API Key。
- 前端和普通 API 只显示“已配置”和末四位，不返回完整 Key。
- Key 不进入日志、审计详情、错误文本、导出或浏览器本地存储。
- 模型调用由 Django 代理，浏览器不直接携带 Key 请求模型服务。
- 用户可替换或删除自己的 Key；管理员只能看到配置状态，默认不能查看原文。

### 11.2 记住登录

登录页增加“记住登录”选项：

- 未勾选时，会话随浏览器会话结束或短期超时失效。
- 勾选时，使用长期、随机、可撤销的 Django 会话 Cookie，默认有效期 30 天。
- Cookie 使用 `HttpOnly`、`SameSite=Lax`；在 HTTPS 部署后启用 `Secure`。
- 系统绝不在浏览器或数据库中保存可逆登录密码。
- 用户退出、密码修改、账号禁用或管理员撤销会话后，自动登录立即失效。
- API Key 与用户账号绑定，因此重新登录后仍可使用；退出登录不会删除已保存的 Key，只有用户主动删除或管理员执行凭据清除才删除。

## 12. 错误处理

错误按来源分类：输入校验、权限、账号离线、登录失效、风控、候选人身份不确定、页面结构变化、CLI 超时、文件失败、系统错误。前端展示可理解的中文信息和建议动作，不统一使用“Request failed”。

批量任务允许部分成功。已成功项目保持成功，失败项目可单独重试。高风险错误必须暂停账号队列，而不是自动无限重试。

- 外发前后双重权限和额度校验；
- 简历哈希去重和招聘转员工；
- Vue 顶部业务切换、侧栏导航和关键交互；
- API Key 掩码、加密存储和不泄露验证；
- 记住登录、退出、密码修改和会话撤销；

验收时必须证明原考勤测试继续通过，招聘模块失败不会影响考勤页面，且压缩包中的第三方候选人和简历未进入系统。
