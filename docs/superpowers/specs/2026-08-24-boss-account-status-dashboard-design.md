# BOSS 账号实时状态与招聘看板设计

日期：2026-08-24

## 目标

修复 BOSS 账号长期停留在“尚未检查/任务进行中”的问题，让 HR 能实时理解每个隔离账号的登录状态、主动重新登录，并在招聘看板同时看到今日工作、异常事项、招聘漏斗和岗位进度。

本设计继续遵守现有安全边界：账号隔离浏览器运行在 Windows；所有真实外发仍需人工确认；状态检查不得绕过扫码、安全验证或平台风控。

## 账号登录态

### 状态模型

界面使用以下可操作状态：

- `unknown`：尚未取得有效检查结果。
- `browser_stopped`：隔离浏览器未运行，但本地登录资料仍保留。
- `waiting_login`：浏览器已打开，等待 HR 登录。
- `waiting_human`：需要 HR 完成安全验证。
- `ready`：账号已登录，可执行授权操作。
- `error`：检查过程异常。

`verification_status` 继续记录 `token_invalid`、`risk_control` 等具体人工处理原因。界面将原因转成清晰文案，不把数据库枚举值直接展示给 HR。

### 登录态复用

每个账号继续使用独立且固定的 Edge `user_data_dir`。浏览器 Cookie、本地存储和平台会话保存在该目录，因此关闭工作台或重启电脑后会优先复用登录状态。只有 BOSS 主动使会话过期、要求扫码、触发安全验证或本地资料损坏时才重新登录。

“重新登录”会打开该账号原有的隔离浏览器环境，不复制日常 Edge 资料，也不清除其他账号数据。系统不存储 BOSS 密码，不尝试自动填写密码或绕过验证。

### 实时检查

- Worker 每 30 秒检查所有启用账号的 CDP 页面状态。
- 前端账号页每 5 秒刷新已持久化的状态。
- “立即检查”触发一次高优先级检查，但不会重复创建相同检查任务。
- “打开/重新登录”启动或聚焦隔离浏览器，并进入等待人工登录状态。
- 状态检查与普通职位、候选人、消息任务解耦，避免一个长任务导致所有账号状态停止更新。

### 超时与恢复

租约过期的 `leased` 任务和执行时间超限的 `running` 任务均可被回收。被回收任务记录失败原因和审计事件，账号退出“任务进行中”状态。Worker 重启后会先完成回收，再领取新任务。

状态检查失败只影响对应账号，不影响其他账号和招聘看板。连续检查错误显示最后成功检查时间、错误摘要和重新检查入口。

## 招聘看板

### 信息层级

1. 顶部指标：在招职位、活跃候选人、待收简历、待安排面试、可用 BOSS 账号。
2. 今日工作：待联系、待筛选、待面试安排、待人工确认以及今日失败任务。
3. 异常提醒：登录失效、风控验证、浏览器停止、自动化失败和长时间未处理事项。
4. 招聘漏斗：新增、沟通、简历、筛选、面试、Offer、录用各阶段人数及转化关系。
5. 岗位进度：岗位、负责人、目标人数、当前候选人、面试人数、录用人数和完成比例。
6. 趋势与动态：近 7/30 天新增候选人、简历、面试、录用趋势，以及最近自动化任务结果。

### 空状态

没有数据时不再显示“后续阶段接入”。每个区域独立显示原因与入口，例如“尚无同步职位—前往职位管理同步”“没有候选人—前往候选人库”“账号尚未登录—打开登录浏览器”。部分数据为空时，已有区域仍正常显示。

### 接口结构

招聘看板接口一次返回：

- `metrics`：顶部指标。
- `today_actions`：今日待办数量及目标页面。
- `alerts`：按严重程度排序的异常列表。
- `funnel`：稳定阶段键、中文标签和数量。
- `job_progress`：岗位级招聘进度。
- `trend`：日期序列及候选人、简历、面试、录用数据。
- `recent_tasks`：最近任务及结果。

所有统计限定为当前用户有权访问的 BOSS 账号和招聘数据。单个统计失败时接口返回该区域的空数据与错误标识，而不是让整个看板失败。

## 前端交互

账号表格直接显示状态圆点、状态文案、最近检查时间和登录态是否可复用。账号操作菜单根据状态提供：

- 已登录：立即检查、同步职位、同步沟通状态、重新登录。
- 等待登录或验证：打开登录浏览器、立即检查。
- 浏览器未启动：打开登录浏览器、立即检查。
- 检查失败：重新检查、重新登录。

看板保持现有简约视觉体系：白色卡片、深色文字、青绿色状态与交互色、线性本地图标。告警使用克制的橙红色，仅在确实需要人工处理时出现。

## 防止空白页回归

生产构建后的发布顺序固定为：前端构建、Django `collectstatic`、服务重启。启动验收脚本必须请求当前 `index.html` 引用的 JS/CSS，并断言响应状态为 200 且 MIME 分别为 JavaScript 和 CSS，防止静态资源缺失时被 SPA 回退页伪装成成功响应。

## 测试与验收

- 后端测试覆盖持久化登录态、状态分类、周期检查、运行中任务超时回收、权限隔离和看板统计。
- 前端测试覆盖所有账号状态文案、操作入口、轮询更新、看板正常/部分为空/全空状态。
- 浏览器验收覆盖页面资源加载、账号状态刷新、重新登录入口、看板各区域和窄桌面宽度。
- Windows 启动验收确认一个 Web 服务、一个 Worker，以及 JS/CSS MIME 正确。

完成标准：页面刷新不再空白；账号状态在 30 秒内反映实际隔离浏览器状态；登录资料可在重启后复用；过期任务不会永久卡住；招聘看板在有数据和无数据情况下都提供可操作信息。
