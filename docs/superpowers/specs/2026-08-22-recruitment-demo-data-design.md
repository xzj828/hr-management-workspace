# 招聘模块演示数据与页面设计

日期：2026-08-22  
状态：已由用户确认

## 1. 目标

在不读取压缩包内第三方候选人和简历数据、不调用 BOSS CLI 的前提下，为招聘模块提供一套可重复加载、可一键清除的本地演示数据，并完成职位管理、候选人、招聘流程和简历中心四个页面的可用 Demo。

本次演示数据包括：

- 3 个虚构职位；
- 10 位虚构候选人；
- 10 条候选人与职位之间的应聘记录；
- 3 份与候选人关联的真实 PDF 简历文件。

所有姓名、联系方式、工作经历和教育经历均为虚构信息，不使用现有压缩包中的 314 条候选人记录或 6 份简历。

## 2. 核心原则

- 演示数据写入本地数据库，各页面通过真实 API 读取，不在 Vue 组件中写死。
- 每条演示记录具有明确标识，与以后从 BOSS 同步或人工录入的业务数据隔离。
- 加载操作具备幂等性，重复执行不会重复创建记录或 PDF。
- 清除操作只删除演示数据及其生成文件，不影响真实业务数据。
- Mock 数据不启动浏览器、不连接 BOSS 账号、不创建 RPA 任务。
- 本阶段不实现大模型评分，简历仅显示“待 AI 评估”。

## 3. 数据模型

沿用现有 `RecruitmentJob`、`Candidate` 和 `JobApplication` 模型，并为需要清理的数据增加演示数据标识。新增 `Resume` 模型保存：

- 关联候选人；
- 关联应聘记录或目标职位；
- 原始文件名、存储文件、MIME 类型与文件大小；
- 来源类型，本次演示数据标记为 `demo`；
- 处理状态与上传时间；
- 演示数据标识。

演示数据由稳定的批次标识或固定外部键定位。加载服务先查询已有记录，再进行新增或更新，以保证重复加载结果一致。

删除顺序遵循关联关系：简历文件与简历记录、应聘记录、候选人、职位。服务在删除前严格过滤演示标识，不允许无条件批量删除。

## 4. 演示数据内容

创建 3 个不同部门和状态的招聘职位，将 10 位候选人分配到这些职位，并分布在以下阶段：

```text
新候选人 → 初筛 → 沟通 → 面试 → Offer → 已入职
                               └→ 淘汰
```

候选人应覆盖不同城市、年限、当前岗位和招聘负责人，以便验证搜索、筛选和看板展示。3 位候选人关联实际生成的 PDF 简历，其余候选人显示“暂无简历”。

PDF 文件包含虚构的个人概况、技能、工作经历和教育经历，可在浏览器中预览并下载。系统只生成 PDF，不为 BOSS 拉取流程设计图片简历入口。

## 5. 页面设计

### 5.1 职位管理

展示职位名称、部门、招聘人数、负责人、候选人数和职位状态。主要操作通过点击整行进入详情，避免在列表中堆叠显眼按钮。

### 5.2 候选人

展示 10 位候选人的姓名、当前岗位、城市、应聘职位、招聘阶段和简历状态。支持按姓名、职位和阶段筛选。点击候选人后使用侧边详情展示联系方式、进度、负责人及关联简历。

### 5.3 招聘流程

使用看板按阶段展示候选人。允许将候选人拖到另一个阶段，并通过 API 保存 `JobApplication.stage`。保存失败时恢复原位置并显示轻提示，避免页面和数据库状态不一致。

### 5.4 简历中心

展示 3 份 PDF 的候选人、应聘职位、来源、更新时间、文件大小和“待 AI 评估”状态。支持浏览器内预览和下载；文件缺失或损坏时显示“文件不可用”，不影响其他列表。

四个页面沿用当前人事管理系统的简约视觉风格和内容区顶部导航，不增加新的侧边栏层级。

## 6. 演示数据入口

在招聘页面内容区右上角提供一个低视觉权重的“演示数据”文字入口。展开后显示：

- 加载演示数据；
- 清除演示数据；
- 当前演示数据状态。

清除操作必须二次确认。加载和清除期间禁用重复操作，并在完成后刷新当前页面。空数据状态提供简短说明，但不使用大面积营销式卡片或过多按钮。

## 7. API 与权限

新增受登录保护的演示数据接口：

- 查询演示数据是否已加载及各类记录数量；
- 幂等加载演示数据；
- 清除演示数据。

完善现有招聘接口：

- 职位和候选人列表提供页面所需的关联统计与筛选；
- 应聘记录允许在授权范围内更新招聘阶段；
- 简历提供列表、详情、PDF 预览和下载所需字段。

演示数据接口复用当前登录权限。服务端负责限制清除范围，不能依赖前端传入的筛选条件保证安全。

## 8. PDF 存储

3 份 PDF 由可重复执行的后端服务生成并存放在 Django 媒体目录中。数据库只保存相对存储路径和元数据，不保存机器相关的绝对路径。

生成文件使用浏览器兼容的 `application/pdf` 类型。删除演示数据时同步删除本批次生成的文件；普通简历文件不受影响。

## 9. 异常处理

- 数据库写入与关联记录创建使用事务，失败时不留下半套演示数据。
- PDF 生成失败时回滚本次加载，并清理已经生成的临时文件。
- 页面请求失败时保留已有内容并显示非阻塞提示，不显示空白页。
- 看板阶段更新采用乐观交互；服务端失败后回滚 UI。
- PDF 不存在时返回明确的不可用状态，不伪装成可预览文件。

## 10. 测试与验收

后端测试覆盖：

- 首次加载生成准确的 3 个职位、10 位候选人、10 条应聘记录和 3 份简历；
- 重复加载不产生重复数据或文件；
- 清除仅影响演示数据；
- 未登录用户不能调用演示数据接口；
- 阶段更新成功与非法阶段拒绝；
- PDF 元数据、文件响应和缺失文件处理；
- 加载失败时数据库与文件回滚。

前端测试覆盖：

- 四个页面正确呈现数据、筛选和空状态；
- 候选人侧边详情；
- 看板拖动成功与失败回滚；
- PDF 预览和下载入口；
- 演示数据加载、二次确认清除及错误提示。

人工验收顺序：

1. 登录系统并加载演示数据。
2. 检查职位管理显示 3 个职位及正确候选人数。
3. 检查候选人页面显示 10 人并验证筛选和侧边详情。
4. 在招聘流程中拖动一位候选人，刷新后阶段保持一致。
5. 在简历中心预览并下载 3 份 PDF。
6. 再次加载，确认数量不变。
7. 清除演示数据，确认四个页面恢复空状态且真实数据未受影响。

## 11. 交付边界

本次不包含：

- 从 BOSS 真实拉取候选人或简历；
- 大模型配置、简历解析、评分或推荐；
- DOC/DOCX 或图片简历转换；
- 自动沟通、邀约或其他外发动作。

这些能力后续可以在相同数据模型上继续扩展，不需要推翻本次页面和演示数据结构。
