# 西鸣人事管理系统

本项目是运行在 Windows 本机和办公室局域网内的人事管理系统。前端使用 Vue 3，后端使用 Python / Django，本地数据库使用 SQLite，当前包含招聘管理和考勤管理。

## 已包含的功能

- 账号密码登录，以及管理员、HR、主管、只读角色基础结构。
- 人员档案、人员标签和考勤策略分别管理。
- 导入飞书打卡 `.xlsx`，按工号优先、姓名/别名兜底匹配。
- 空白或 `-` 算休息，有打卡算出勤。
- 识别“次日”记录，以及第二天单条凌晨打卡的跨日疑似。
- 跨日疑似人工审核：归前一天或保留当天。
- 弹性工作和免考勤人员按应出勤天数正常计薪。
- 考勤结果人工调整、确认、规则轨迹和 Excel 汇总导出。
- 看板支持起止月份跨月查询和部门筛选，并提供每日出勤率折线图、部门对比、个人上下班曲线和异常看板。
- 原始上传文件留档、重复文件校验和本地备份脚本。
- BOSS 账号使用独立 Chrome 或 Edge 用户目录，可由本机 Worker 检查登录状态、打开人工登录页和只读同步职位。

## 第一次使用

1. 双击 `初始化系统.cmd`。
2. 按提示设置管理员密码。默认管理员账号为 `admin`。
3. 初始化脚本会自动导入参考表中的人员档案（参考表存在时）。
4. 完成后双击 `启动考勤系统.cmd`。
5. 保持运行终端窗口打开，浏览器访问终端显示的本机或局域网地址。

需要修改登录密码时，双击 `修改管理员密码.cmd`，按提示输入两次新密码。

## 日常运行

双击 `启动考勤系统.cmd`。前端已经构建进 Python 服务，启动窗口会同时管理 Web 服务、本机 RPA Worker 和 AI 处理 Worker；关闭窗口或按 `Ctrl+C` 会停止这些精确进程。

本机默认地址：`http://127.0.0.1:8000`

局域网同事可使用终端中显示的局域网 IP 地址访问。Windows 首次弹出防火墙询问时，需要允许“专用网络”。

## BOSS 招聘自动化

先在 PowerShell 执行 `boss --version`，应能看到已安装的 `@joohw/boss-cli` 版本；本项目已按 `0.6.6` 验证。系统不会复制或修改 CLI 源码，只调用本机安装的命令。

首次使用流程：

1. 进入“招聘管理 → 管理后台 → BOSS 账号与浏览器”，添加账号并选择 Chrome 或 Edge。
2. 在账号的省略号菜单选择“打开登录浏览器”。系统会打开该账号专属的隔离浏览器目录。
3. 由 HR 本人扫码或登录。验证码、App 确认、安全验证和风控页面必须人工完成，系统不会尝试绕过。
4. 登录完成后选择“检查状态”，确认账号显示为已登录。
5. 选择“同步职位”只读取职位列表，并按 BOSS 职位编号幂等新增或更新职位名称与状态。
6. 在“招聘作业台”选择岗位、账号和标准方案，填写招聘要求、目标人数与扫描上限后执行。“被动咨询”会同步完整消息：明确表示想了解公司或岗位时创建人工介入待办，明确拒绝时停止，其余候选人使用 BOSS 原生“索要简历”动作；同步间隔可按账号设置为 1 到 1440 分钟。
7. “主动寻访”可选择推荐、常规搜索或深度搜索，设置“目标合格简历数”和“AI 最大分析份数”。Worker 最多拉取分析上限数量的在线简历，AI 按已发布岗位标准逐份评分；达到合格目标或完成分析上限后停止，HR 可在结果中心筛选并批量确认统一话术，后台再逐人串行打招呼。
8. BOSS 在线简历按 CLI 实际产物保存为 PNG 长图；候选人在沟通中发送的附件简历保存为 PDF。两者都按 SHA-256 去重、保留版本，并在“简历中心”提供查看和下载入口。
9. “招聘作业台”可按职位上传 `.doc`、`.docx` 或多工作表 `.xlsx` 岗位需求、候选人画像和补充标准，也可同时手动填写核心要求与加分项。系统会把上传内容与手动文本合并、去重并归一化成 100 分的标准草稿；必须由 HR 检查权重、60 分线、来源和敏感项排除结果后确认启用。
10. 评分标准支持手工录入硬性指标，并为自动淘汰配置结构化字段、比较条件和阈值。只有简历结构化字段明确违反规则才会淘汰；字段缺失只标记“信息不足”。系统会记录规则、实际值、证据和审计日志，大模型单独给出的 `not_met` 不会直接改变招聘阶段。
11. PDF、PNG 在线简历统一结构化后，HR 可勾选批量评分。新版 AI 只返回 L0–L4 证据等级、缺失/矛盾状态和逐字原文引用，服务端按固定比例计算总分、执行 60 分线和系统建议；AI 正式报告独立持久化并可单独重试。评分、报告、HR 结论和招聘阶段彼此独立，不自动推进或淘汰候选人。
12. “结果中心”集中展示运行结果、候选人/简历/评分、招聘阶段，以及候选人观望、身份不明确、主动寻访后需要打招呼等人工事项；处理后可直接标记完成。所有任务、节点和待办保留状态、时间和审计记录。
13. “管理后台 → 流程方案”的高级画布支持新增、删除、移动和重排业务节点，自定义连接任意两个合法节点，并可为连线配置消息意图条件。每次保存生成不可变版本，正式运行冻结该版本快照；运行行为严格以保存的画布为准，删除动作节点后不会在同步步骤中暗中执行该动作。

隔离资料默认位于 `backend/rpa_profiles/`，每个账号拥有独立目录和调试端口，不使用日常 Edge/Chrome 的用户资料。浏览器用户目录会保留 BOSS 登录会话；会话失效、验证码、风控、同名歧义或页面身份错位时，任务会暂停或转人工，不会尝试绕过验证。当前自动外发只开放简单求简历动作；面试邀约和复杂自动对话不在第一、第二阶段范围内。

BOSS CLI 的候选人列表不一定提供稳定平台 ID。系统会明确标记“平台身份”或“组合指纹”；组合指纹只用于发现池和本地去重，未来执行任何外发动作前都必须重新打开页面并核验目标，不能依赖姓名发送。

## 自定义模型安全配置

顶栏“切换模型”可选择当前账号已保存的模型，也可新增 OpenAI 兼容模型。默认只接受解析并连接到公网地址的 HTTPS URL；系统拒绝 URL 内的用户凭据、查询参数、片段、重定向，以及回环、私网、链路本地和保留地址。API Key 只加密保存在服务端，列表与详情仅返回是否已配置和末四位。

确需连接本机或内网模型时，部署管理员可在启动服务前设置 `MODEL_API_HOST_ALLOWLIST`，值为逗号分隔的精确 `host` 或 `host:port`（IPv6 端口形式为 `[::1]:11434`），例如 PowerShell：`$env:MODEL_API_HOST_ALLOWLIST="localhost:11434"`。允许列表会同时放宽 HTTP 和受限网络地址检查，只应填写由本机管理员控制的可信端点，不能把该变量交给普通工作台用户。可用 `MODEL_API_MAX_RESPONSE_BYTES` 调整单次模型响应体上限（默认 1 MiB），用 `MODEL_API_TEST_TIMEOUT_SECONDS` 调整连接测试超时（默认 10 秒），用 `MODEL_API_TEST_THROTTLE_RATE` 调整每用户测试频率（默认 `5/min`）。API Key 接受 8–4096 个字符。

### 真实账号验收边界

自动化测试和演练不会对真实候选人发送内容。第一次验证写操作时，应由 HR 在 BOSS 中指定 1 名测试候选人，只验收一次“索要简历”。验收应确认：目标身份唯一、原生按钮执行正确、成功项不会重复、验证码出现后账号暂停、PDF 附件与候选人/职位正确关联。未指定测试候选人前，只运行搜索、读取、在线简历拉取、确认队列和本地数据验收。

此前压缩包中的 314 条候选人记录和 6 份简历属于其他公司，本系统不会导入、读取或用于测试这些数据。

## 招聘演示数据

职位管理、候选人、招聘流程和简历中心页面右上角提供“演示数据”入口。加载后会在本地数据库中创建 3 个虚构职位、10 位虚构候选人、10 条应聘记录和 3 份生成的 PDF 简历，用于查看页面与流程效果。

演示数据具有独立标记，重复加载不会产生重复记录。“清除演示数据”只删除这些演示记录和对应 PDF，不影响真实业务数据。该过程不调用 BOSS CLI、不启动浏览器，也不会读取此前压缩包中的第三方候选人或简历。

## 数据位置与备份

- 本地数据库：`backend/db.sqlite3`
- 原始上传文件：`backend/media/attendance_imports/`
- 招聘岗位依据和简历：`backend/media/recruitment/`
- 一键备份：双击 `备份本地数据.cmd`

备份会复制 SQLite 数据库和 `backend/media/` 原始文件到 `backups/日期时间/`。模型 API Key 只以当前登录账号的加密凭证保存在数据库中，`local_secret.key` 也必须随设备迁移安全保管，否则无法解密已有 Key。

## 当前规则边界

第一版严格执行“空白/`-` 为休息，有记录为上班”。请假、加班审批、调休和出差无法仅从打卡机文件判断，需要在核算结果中人工补充。迟到规则字段已经预留，但在没有确定各岗位班次前不自动扣款。
