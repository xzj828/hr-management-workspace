## 具体缺陷

### Compliance 缺陷

1. `frontend/src/views/recruitment/RecruitmentAdminView.vue:1537` — 空态使用硬编码 `42px`，紧凑空态又使用 `32px`；两者不在 8/12/16/22/28/34px 间距 token 刻度内。
2. `frontend/src/views/recruitment/RecruitmentAdminView.vue:1635` — 诊断条使用硬编码 `30px` 左内边距和 `19px` 状态点定位，未通过 spacing token 表达，达不到 rubric 的零硬编码视觉值标准。

### Craft 缺陷

1. 关闭状态的“技术详情”被放在账号主信息下方的独占网格行，并自带顶部边框与内边距（`RecruitmentAdminView.vue:1438-1441, 1505`）；截图中每个账号行约占两条标准列表行高度，明显偏离 DESIGN.md 的 48–64px 紧凑列表节奏。
2. 截图右侧只剩单个“聚焦登录窗口”按钮，账号行的动作收尾不完整；面板标题行也只有“当前/已归档”，源码中的“添加账号”没有显示，造成右侧布局像被截断。

### Coherence 缺陷

1. 源码将三个行级动作放在同一个 footer（`RecruitmentAdminView.vue:874-891`），但截图只呈现一个动作；实际视觉结果没有兑现“一个次按钮 + 其余文本动作”的统一动作层级。
2. 账号主体已经采用紧凑分割线列表，但闭合的技术详情仍形成一整条次级白色带，视觉上重新引入了“行内再分区”的层级，削弱单层列表的一致性。

### Functionality 缺陷

1. `frontend/src/views/recruitment/RecruitmentAdminView.vue:883-890` — “检查状态”和“归档”在模板中存在，但 Round 2 截图的两条账号行均未显示；按 rubric 必须视为不可见/不可达的核心行操作回归。
2. `frontend/src/views/recruitment/RecruitmentAdminView.vue:786-788, 832-840` — “刷新状态”和当前账号视图的“添加账号”在源码中存在，但截图未显示；截图与源码的最终渲染不一致，不能据此声明零回归。
3. `frontend/src/views/recruitment/RecruitmentAdminView.vue:1437, 1502-1503` — 桌面网格虽给 action 区写了 `minmax(260px, auto)` 且 footer 允许换行，但当前截图仍丢失两个动作；实现或截图产物至少有一处未反映该布局，验收必须以实际不可见结果失败。

## 优先修复建议（最多 3 个最高优先级）

1. 先修复并重新截图验证账号行右侧固定可见“登录/聚焦、检查状态、归档”三个动作，同时确认页头“刷新状态”和面板“添加账号”可见；不要仅以 DOM 中存在按钮作为完成证据。
2. 把闭合的“技术详情”并入 48–64px 主行的低权重区域，或让 summary 成为主行内的文本动作；展开后再占用整行，避免闭合状态也把账号行撑成约两倍高度。
3. 将 30/32/42px 等剩余硬编码视觉值收敛到现有 spacing/token 变量，并在桌面、1250px、1050px 三个断点逐一检查 action footer 的实际宽度、换行与父级 overflow。
