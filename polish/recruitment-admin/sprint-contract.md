# Sprint Contract: 管理后台

## Baseline

- 总分：10/20
- 最差维度：Compliance / Craft / Coherence（均 2）
- 截图：`polish/baseline/recruitment-admin-before.png`

## Gap 分析

- 页面自定义第二套绿色 `#0f7655`，与全局 `--teal` 不一致。
- Hero、Tab、Section Header、Item Card 四层容器；账号和诊断使用卡片网格，信息被切碎。
- 每个账号同时出现两个实心/描边按钮和归档链接；端口、隔离目录在首屏占据高权重。
- Section Header 使用 19–21px 大内边距与 14px 圆角，和主数据容器形成重复卡片。
- 工作流、模型、账号三种列表视觉语言不同。

## 验收标准

1. 仅保留页头、文本 Tab 和一个主内容面板；Section Header 不再表现为独立卡片。
2. 账号、流程、模型统一为有分割线的列表行；诊断为紧凑状态条，不再四卡网格。
3. 页级只有“添加账号/新建流程/新增模型”等一个主按钮；行内主要操作为次按钮，其余为文本动作。
4. 技术详情降为弱文字或折叠区域，状态和下一步仍可在 3 秒内识别。
5. 颜色、圆角、阴影和字号匹配 `DESIGN.md`；所有功能和四态不回归。

## PASS 阈值

总分 ≥16/20，且无单项 ≤2。

## 改动边界

允许改 scoped CSS、类名和非语义容器；不改 API、权限、状态机和生命周期逻辑。
