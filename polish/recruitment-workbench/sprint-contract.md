# Sprint Contract: 招聘作业台

## Baseline

- 总分：11/20
- 最差维度：Compliance / Craft（2）
- 截图：`polish/baseline/recruitment-workbench-before.png`

## Gap 分析

- 连续的岗位准备流程被多张卡片拆开，页面纵向边框和标题重复。
- 左侧准备区和右侧执行摘要都强调输入内容，造成视觉重复。
- 方案选择、数量和检查结果存在多个高权重按钮/状态块。
- 自定义字号和浅色背景过多，未形成考勤模块的“页头 → 工具/主面板”节奏。

## 验收标准

1. 岗位依据、招聘要求、执行方案呈现为同一主面板内连续编号分区，分区之间使用分割线。
2. 右侧摘要弱化为简洁粘性栏，仅保留关键选择、阻塞项和唯一“开始执行”主按钮。
3. 页面同屏最多一个实心主按钮；上传、添加条件、管理入口降级。
4. 桌面和 720px 以下均无横向溢出，功能与表单状态不回归。

## PASS 阈值

总分 ≥16/20，且无单项 ≤2。

## 改动边界

仅改视觉与非语义容器；不改运行、上传和恢复逻辑。

# Sprint Contract Revision: 蓝色紧凑工作台（2026-08-26）

> 上述契约保留为历史证据；本节是本轮 Generator 与 Evaluator 使用的最新验收契约。

## Baseline

- 聚合均分：11.0/20（context 12、standard 10、plan 11）
- 最差维度：Design System Compliance 2.0 / Visual Craft 2.3
- 评分卡：`polish/recruitment-workbench/blue-baseline-scorecard.md`
- 截图：`baseline-context.png`、`baseline-standard.png`、`baseline-plan.png`

## Gap 分析

### Compliance 缺陷

- [ ] 用户指定的页面级蓝色画布未实现；当前仍以 `#f3f6f8` 为工作台底色。
- [ ] hover、selected、warning、drop-zone、success、error 仍在规则内散落十余个硬编码色值，未收敛到 `--wb-*` 语义 token。
- [ ] 普通白卡只使用近乎不可见的标准面板阴影，未形成用户要求的蓝底白卡层级。
- [ ] 业务说明与阻塞原因大量使用 10–11px；与 12–13px 控件/正文层级不匹配。

### Craft 缺陷

- [ ] 步骤条和主卡无工作台专属宽度上限；大屏横向铺满，字段内容与控件宽度失衡。
- [ ] `standard` 的上传区最小高度 224px，和两列文本域叠加后形成无效长页。
- [ ] `plan` 在 viewport ≤1700px / container ≤1320px 即强制单列，使常见桌面退化为两张纵向长卡。
- [ ] 程序化聚焦的步骤标题暴露原生黑色焦点框。
- [ ] 两个 textarea placeholder 显示字面量 `\n`，内容完成度不合格。
- [ ] 方案 radio 被完全隐藏，选中状态主要依赖边框颜色。

### Coherence 缺陷

- [ ] 当前灰白/青绿内容区没有形成参考图所要求的“蓝色舞台 + 白色主卡”视觉主语。
- [ ] 前两步单卡、最后一步双卡纵向堆叠，密度与阅读节奏不一致。
- [ ] 英文 eyebrow、微小元信息和大面积空白同时存在，视觉噪音与信息稀疏并存。

## 验收标准

1. 工作台内容区使用唯一页面级平面蓝色 token；不得影响侧栏、顶栏或其他路由。三个步骤截图都必须清楚看到蓝色 gutter。
2. 页头、向导和内容区在桌面居中，最大宽度 `980px`；向导改为蓝色舞台上的紧凑步骤导航，不再呈现一条横向白色长卡。
3. 主面板与检查面板保持白色、15px 圆角；使用已记录的浮层阴影 `0 18px 48px rgba(15,23,42,.15)`，无 hover 上浮。
4. `plan` 在 viewport >1050px 且空间足够时保持主区 + 304–320px 检查栏；≤1050px 收为单列；页面自身无横向溢出。
5. 上传区桌面最小高度压缩到 160–176px，textarea 维持可读但不过高；`standard` 的主要下一步动作在常见 1280×720 桌面接近首屏可达。
6. 页面标题沿用 27px/700；区块标题 17–20px/700；业务正文、阻塞原因和主要说明不小于 12px，10px 只用于 STEP/meta。
7. 步骤标题不再显示黑色原生字符框；保留程序化焦点与清晰的当前步骤状态。
8. placeholder 使用真实换行，截图与 DOM 中不出现字面量 `\n`。
9. 方案选择保留原生 radio 语义，并提供非颜色的可见选中标记；hover、focus、selected 四态可辨。
10. 新增或调整的所有颜色只定义在页面级 token 区；具体规则引用变量，不新增散落 hex/rgb/hsl 值。
11. 三个步骤在默认桌面视口及 720px 窄屏均无重叠、裁切或横向溢出；前进、后退、选择与禁用原因可见。
12. 定向 Vitest、完整前端 Vitest、生产构建通过；浏览器控制台无新增错误。

## PASS 阈值

总分 ≥16/20，且无单项 ≤2；Functionality 必须为 5。

## 改动边界

- 允许改：`RecruitmentWorkbenchView.vue` 的 scoped CSS、非语义视觉容器/文案呈现、页面级 token；必要时可增加仅用于样式的 class。
- 禁止改：路由、API、上传/运行/恢复逻辑、权限、确认与安全门、响应数据结构。
- 不引入依赖，不修改其他业务页，不使用背景图片或影响表单可读性的夸张装饰。

## 用户视觉自由度补充（2026-08-26）

用户明确允许整页渐变、玻璃效果和阴影，但不要求必须使用。本轮可使用非常克制的深浅蓝整页渐变与柔和白卡阴影增加质感；是否使用以“简约但不简陋”和表单可读性为判断标准，避免多层玻璃容器或效果堆叠。
