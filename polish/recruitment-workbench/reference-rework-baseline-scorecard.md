# 招聘作业台参考图重做 Baseline Scorecard

评审日期：2026-08-26
评审对象：`frontend/src/views/recruitment/RecruitmentWorkbenchView.vue` 与四张当前截图
视觉硬标准：用户提供的 1522×1371 参考原图，仅提取构图、色彩强度、比例、排版与层级，不复制 BOSS 品牌元素。

## 结论

**11/20 — NEEDS_IMPROVEMENT**

当前版本功能轮廓完整，且基础表单组件大体沿用项目 token；但第一眼仍是“传统后台页面上放了一张横向表单卡”，没有形成参考图的“高饱和青蓝全页舞台 + 居中统一大卡 + 左浅青导航区 + 右白工作区”。用户已经否决当前视觉，因此它不能作为可接受的终态。

本轮优先级处理：Design System Compliance 仍按 `DESIGN.md` 与代码核验；Visual Craft、Coherence 则把参考图构图相似度和第一眼专业度作为硬标准。参考图对大面积背景色形成了用户明确指定的页面级特例；后续若要获得高合规分，应把该特例固化为正式的 workbench stage token，不能继续使用临时局部色值。

## 可执行重做建议（最多 5 条）

1. **先重建舞台与唯一外框。** 让 workbench 路由在可用视口内形成高饱和青蓝沉浸舞台；若保留应用 Shell，也必须让 Shell 退居导航层，舞台和主卡成为第一视觉。建立正式的 page-level stage token，颜色取参考图强度但用西鸣自己的青蓝，不复制任何 BOSS 标识。
2. **三个步骤共用同一个稳定的大卡尺寸。** 桌面端目标宽高比控制在约 1.3–1.6，而不是 Step 1 当前约 3.3；在 1280×720 级视口中优先获得约 600px 的可见卡高。外圆角提升到约 32–40px，使用克制但清晰的单一外框阴影；内容多少只影响右区内部滚动，不改变整卡轮廓。
3. **把横向步骤条改为卡内左侧浅青面板。** 左区占约 32–35%，纵向呈现 01/02/03、完成/当前状态和极简业务说明；右区占其余宽度，只承载当前步骤。Hero 标题移入右区顶部，Step 3 的检查摘要可进入左区下部或右区末端，删除独立的 `workbench-review` 外卡视觉。
4. **放大并收敛排版层级。** 当前步骤标题提升到约 26–30px，关键说明/控件到 14–16px，辅助文字保留 12–13px；右区使用 28–40px 的稳定内边距、48px 左右控件高度和更长的纵向节奏。首屏移除 CDP、浏览器端口等技术信息，仅保留岗位、账号业务状态和下一步。
5. **在不改事件与业务状态的前提下重排 DOM/CSS。** 保留现有三步路由、上传队列、校验、方案参数、执行控制和唯一主动作；≤720px 时仍保持“一个圆角外框”，把左面板折叠成卡内顶部步骤/摘要区，再呈现右侧工作区，避免当前图标侧栏 + 散落标题 + 长表单的简单堆叠。
