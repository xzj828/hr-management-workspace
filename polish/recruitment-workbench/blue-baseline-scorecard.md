# 招聘作业台：蓝色视觉基线评分卡

## 评审范围

- 视觉真值：`DESIGN.md`、`polish/design-tokens.md`
- 评分尺度：`evaluator-rubric.md`
- 实现证据：`frontend/src/views/recruitment/RecruitmentWorkbenchView.vue` 的 template 与 scoped style
- 截图证据：`baseline-context.png`（1280×720）、`baseline-standard.png`（1265×1036）、`baseline-plan.png`（1265×1232）
- 用户目标：简约但不简陋；招聘作业台内容区使用蓝色背景；白色圆角阴影卡片；卡片不过长、不过宽；字号合适。

本次为独立基线评审，未读取任何 Generator 产物。Functionality 仅依据三张静态截图及 template/style 判断；未执行浏览器点击和控制台检查，因此不能给 5 分。

## 分状态判分依据

### 1. 岗位与账号（context）— 12/20

- **Compliance 2/5**：白色表面、15px 面板圆角、9px 控件圆角、Inter/中文系统字体和克制阴影基本沿用 token；但本次最核心的页面级蓝色背景完全没有落地。`RecruitmentWorkbenchView.vue:1638` 仍把 canvas 定义为 `#f3f6f8`，且工作台根节点没有蓝色内容画布。向导 hover/current 等状态仍散落多组未 token 化色值（如 `:1861`、`:1872`、`:1881-1883`）。这不是“1–2 处次要偏离”，只能判 2。
- **Craft 3/5**：标题、步骤条、表单、动作区的阅读顺序明确，但近乎全宽的步骤条和主卡把两个选择框拉得过长；卡片内部横向留白很多，纵向信息却偏小。辅助文案普遍为 10–11px，截图中呈现得过细、过淡。聚焦后的 `h3` 出现紧贴文字的黑色矩形原生焦点框，破坏标题工艺。
- **Coherence 3/5**：页面内部沿用现有灰白/青绿色后台语言，但没有形成用户要求的“蓝色画布 + 白色卡片”主语；黑色原生标题焦点框也明显像未纳入组件系统的浏览器默认样式。
- **Functionality 4/5**：职位、账号、运行状态、禁用原因和下一步动作均可见且无遮挡；template 保留了 disabled、aria-current 与错误态。由于没有实际点击、提交及控制台证据，不能判 5。

### 2. 招聘标准（standard）— 10/20

- **Compliance 2/5**：同样缺少蓝色页面画布；拖拽区直接使用 `#b8c8d8`、`#fbfdfe`、`#f2fbf9`、`#def5f1`（`:2118-2160`），成功/失败队列也使用多组未定义色值（`:2216-2224`），与 rubric 的 token 化要求相距明显。
- **Craft 2/5**：1265px 宽的页面被拉到 1036px 高，单张主卡从标题一直包到页底。224px 固定最小高度的拖拽区（`:2116`）占据过多面积，随后再并排放两个 116px 以上文本域，页面呈现“超大容器里放小字”的失衡。标题同样残留黑色原生焦点框；两个 placeholder 直接显示字面量 `\\n`，视觉完成度不合格。
- **Coherence 3/5**：表单、按钮、分隔线总体仍是同一套组件语言；但巨大的浅青拖拽块成为不成比例的视觉主角，与期望的蓝色画布、白卡层级冲突。`\\n` 文案瑕疵让内容层也显得未收口。
- **Functionality 3/5**：上传、用途选择、文本输入和前后导航都可见，核心功能没有白屏或遮挡；但 `RecruitmentWorkbenchView.vue:1455`、`:1460` 在 HTML attribute 中写入 `\\n`，截图已证明换行未被解析，两个输入框都显示错误提示文案，属于可见的次要功能/内容回归。

### 3. 执行方案（plan）— 11/20

- **Compliance 2/5**：缺少蓝色画布；主卡与检查卡虽使用白色、圆角、克制阴影，但响应式行为偏离 `DESIGN.md` 的 1050px 收单列约束。`:2685-2705` 在 viewport ≤1700px 就强制单列，`:2707-2731` 又在 container ≤1320px 重复强制单列，属于主要布局规则偏离。
- **Craft 2/5**：截图高达 1232px。执行方案和执行前检查被堆成两张接近全宽的大卡，导致页面明显过长；检查卡中的 10–11px 文案又过密、过小。方案卡片的选中态主要靠青绿色边框表达，缺少清晰的选中标记。标题仍出现黑色原生焦点框。
- **Coherence 3/5**：方案选项、表单、检查列表与主动作基本共享圆角和色彩语言；但从“单主流程”突然变成两张纵向大卡，密度与前两步不一致，且颜色仍是灰白/青绿而非本次蓝色工作台方向。
- **Functionality 4/5**：方案选择、流程、参数、检查项、处理链接、禁用主按钮及禁用原因均可见，符合“状态不只靠颜色”和“禁用保留原因”的大部分要求。未做交互与控制台验证，因此不能判 5。

## 严格问题清单（按优先级）

### P0 — 未解决不得进入下一轮验收

1. **用户指定的蓝色内容背景完全缺失。**
   - 证据：三张截图的工作台内容区都是浅灰色；`:1638` 仍为 `--wb-color-canvas: #f3f6f8`，根节点没有蓝色背景。
   - 影响：首要视觉目标未实现，白色卡片也失去应有的蓝白层次。
   - 验收目标：为招聘作业台建立明确、文档化的 page-scoped blue token；只作用于工作台内容区，不扩散到侧栏和其他业务页。三个状态都必须一眼可见蓝色画布及足够的白卡对比度。

2. **卡片缺少工作台专属宽度约束，标准页和方案页明显过长。**
   - 证据：三张截图宽度近似，但页面高度依次为 720 / 1036 / 1232px；standard 的单卡纵向吞并全部内容，plan 则把主卡和检查卡纵向堆叠。
   - 影响：直接违背“卡片不能过长过宽”，页面更像铺满画布的表单容器，而不是克制的作业台。
   - 验收目标：给向导和内容区建立居中的、工作台专属的合理 max-width，让蓝色 gutter 清晰可见；桌面空间足够时，方案与执行前检查保持主次并列。只有接近设计约束的窄屏阈值时才收为单列，不能在 1700px 就无条件塌陷。

3. **方案页响应式断点直接制造超长页面。**
   - 证据：`:2685-2705` 的 `@media (max-width: 1700px)` 与 `DESIGN.md` 的“1050px 以下双列收单列”不一致；另有 container 1320px 的重复塌陷规则。
   - 影响：常见 1280/1440/1600 桌面宽度都失去右侧检查栏，第二张卡被推到主流程下方。
   - 验收目标：以实际可用内容宽度验证断点；在能够容纳主区和约 304–320px 检查栏时保持双列，窄屏再单列，且不能产生横向溢出。

### P1 — 主要工艺与一致性问题

4. **业务信息字号层级偏小，尤其是支持文案和检查项。**
   - 证据：`:1649-1652` 定义 10/11/12/13px；截图中多个关键解释、检查详情和动作提示落在 10–11px，灰度又低。
   - 影响：在 1265–1280px 截图中阅读吃力，“简约”变成了“小而淡”。
   - 验收目标：业务正文与关键说明以 13px 为基线；10–11px 只保留给真正的 metadata/kicker，不承载阻塞原因、下一步解释或主要检查信息。

5. **standard 的拖拽区与输入区密度失衡。**
   - 证据：`:2116` 强制 `min-height: 224px`，`:2294` 文本域至少 116px；两者同时放入单一长卡。
   - 影响：空白面积过大，用户需要滚动才能完成一个本应紧凑的步骤。
   - 验收目标：压缩拖拽区高度和非必要留白；文件区、已上传结果、文字要求形成紧凑而清晰的节奏，主要下一步动作在常见桌面首屏或接近首屏位置可见。

6. **标题的程序化聚焦暴露原生黑色焦点框。**
   - 证据：三张截图中“选择本次作业 / 招聘标准 / 执行方案”均有紧贴字面的黑框；template 在 `:1321`、`:1374`、`:1489` 为标题设置 `tabindex=-1`，scoped style 没有为该聚焦状态建立设计系统样式。
   - 影响：每一步的视觉焦点都像调试态或浏览器默认态。
   - 验收目标：保留无障碍焦点迁移，但用 token 化、可辨识且不破坏标题字形的 focus 样式；鼠标导航不应留下突兀的黑色字符框，键盘用户仍必须获得清晰焦点指示。

7. **standard 的 placeholder 显示字面量 `\\n`。**
   - 证据：截图两个文本域均显示 `例如：\\n...`；来源为 `:1455`、`:1460`。
   - 影响：可见内容错误，直接降低专业感，也误导用户输入格式。
   - 验收目标：使用真实换行或单行示例；三张截图及 DOM 中不再出现字面量 `\\n`。

8. **大量状态色与表面色绕过 token。**
   - 证据：除顶层变量定义外，`:1751-1754`、`:1861-1883`、`:2118-2160`、`:2216-2224`、`:2550-2569` 仍直接写入多组 hex 值。
   - 影响：Compliance 最高只能停留在 2–3 分；蓝色改造时极易出现另一套临时色。
   - 验收目标：把 hover、selected、warning、drop-zone、success、error 的边框/背景/文字全部映射到语义 token；CSS 规则中不再散落未说明的视觉色值。

9. **方案选中态主要依赖颜色边框。**
   - 证据：`:1495-1504` 隐藏原生 radio，`:2331-2335` 选中态仅改变边框，截图中没有稳定的 check/radio 标识。
   - 影响：状态识别弱，也不利于色觉差异用户；两张白卡视觉上过于接近。
   - 验收目标：保留 radio 语义并增加非颜色选中标志；未选、hover、focus、selected 四态清楚且使用同一 token 体系。

### P2 — 次要但应在本轮收口

10. **白卡阴影在浅灰画布上几乎不可见。**
    - 证据：`:1686` 使用极轻的 `0 1px 2px rgba(15,23,42,.025)`；截图主要靠细边界识别卡片。
    - 影响：目前“白色圆角阴影卡片”的阴影表达不足；切换蓝色画布后需重新验证对比。
    - 验收目标：先保持 DESIGN.md 的克制阴影，不做夸张上浮；在最终蓝色背景上确认卡片边界、圆角与阴影都能被看见，必要时通过合规的边框/表面层级解决，而不是任意加大投影。

11. **步骤条与 context 双选择框横向拉伸过度。**
    - 证据：context 截图中步骤条、主卡和两个 select 几乎占满全部可用宽度，字段内容远短于控件宽度。
    - 影响：视觉重心被横向稀释，卡片显得“宽而空”。
    - 验收目标：随工作台 max-width 一并收紧；表单列宽匹配内容，不以 100% 拉伸制造空旷感，同时保留 720px 以下单列响应式。

## 下一轮硬性验收门槛

1. 三个状态都呈现明确蓝色内容画布、白色 15px 圆角卡片与可辨识的克制阴影。
2. standard 与 plan 不再形成 1036/1232px 式的无效长页；plan 在空间足够的桌面保持主区 + 检查栏布局。
3. 关键正文与阻塞信息不使用 10–11px；无字面量 `\\n`；无黑色原生标题焦点框。
4. 页面级视觉状态全部 token 化；新增蓝色不得成为散落的硬编码颜色。
5. 下一轮必须补充实际键盘/鼠标交互与控制台验证，否则 Functionality 仍不得超过 4。
